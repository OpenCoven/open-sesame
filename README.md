# Open Sesame — Widget Studio

A private interactive prototype with a native macOS companion source package. Buildless HTML, CSS, and JavaScript live in `dist/`; the AppKit/WKWebView host and real PTY bridge live in `desktop/`. See [desktop setup](desktop/README.md).

For the current review, priorities, integration gaps, and platform exploration, see the [desktop polish plan](docs/desktop-polish-plan.md).

Run `npm run dev` for the local widget preview, `npm run dev:macos` to build and open `build/Open Sesame.app`, or `npm run build:desktop-source` to regenerate the source download before static hosting. The native executable is `OpenSesame`. Existing browser data migrates to the new storage keys; the installed bundle identifier stays stable to preserve native website data and permissions.

Run `npm run check` for the current widget checks and JavaScript syntax validation. The historical validation notes below describe earlier snapshots; see the plan for the current results and outstanding device checks.

## Interactions

- Toggle notch/menu bar placement and compact/expanded states. Expanded controls retain the requested 20% increase in scale.
- The compact notch uses a uniform silhouette. Playful shape optionally adds a rounder curve and a small lilac sparkle; the classic shape is the default.
- Adjust compact notch width (180–440 px) and width-to-height ratio (5:1–12:1).
- Preview virtual desktops at 1280×800, 1512×982, 1728×1117, and 1920×1080. Inspect enlarges the widget, scaling down when needed to keep it in view. Present hides studio controls.
- Silent music transport, seeking, volume, and favorites fill the music pane without scrolling.
- Focus has fixed 15, 20, 25, 30, 45, 60, and 90 minute periods, plus custom whole-minute periods above 60. The 15/20/25 minute modes allow five topics; 30/45/60 allow ten; periods above 60 have no topic cap. Switching to a mode that cannot hold the current plan is blocked without deleting topics. Topic allocations share the chosen period.
- Five editable topics fit on each page without scrolling. The segmented timeline, current/next topic, actual elapsed time, remaining time, pause/resume/reset, and manual advancement remain visible. The active topic's page opens when the session moves on, with an in-preview notification. Editing a plan resets the session; plans and duration persist locally.
- Notes, bookmarks, and tasks live in one Items section. Categories expand to reveal their project filter and items in one left column; a unified category/item list sits on the left and editable details sit on the right. Each category can be viewed across all projects, in Inbox, or within a named project. Tasks have completion controls and can convert to or from notes.
- Attach copied page link reads the clipboard only after an explicit click, defaults bare page addresses to HTTPS, preserves explicit HTTP(S), accepts only valid page links, and never inserts unrelated clipboard text. Pasting a sentence with a URL into the attachment field extracts the URL. Browser tab discovery is not available to a normal web page and is not simulated.
- Neutral, compact quick capture stays in the footer. Plain text becomes a note; pasted or attached HTTP(S) URLs become bookmarks. Choose Task to capture a to-do. Existing notes, saved URLs, project assignments, and detail bodies migrate to the unified `open-sesame-items-v1` collection; the legacy storage key is retained.
- Open an item to expand its workspace. Titles, bodies, completion, and project membership save on input. Create projects from the rail or project selector. Items use fitted pages. The expanded workspace has exactly two columns in a taller 600 px panel: a unified category, project, and item column on the left, with selected-item details on the right. The left column is capped at 148 CSS px, about 35% narrower than before. Full width in the detail header temporarily hides the list and search, giving notes, tasks, or bookmark previews the entire content width; Show list or Escape restores the split view without reloading the selected item. One category opens at a time, collapsing its peers and selecting a matching item. Each open category includes a project selector; item pages adapt to the remaining height. Long note bodies and transcripts use measured text pages with the full document retained separately. Copy, save, and export actions use the complete document. Bookmark previews occupy a dedicated fitted view instead of extending the detail panel.
- Bookmarks open their sandboxed preview by default. One 27 px toolbar holds a quiet editable title, project picker, compact Preview/Notes tabs, URL edit, full-width/list, delete, privacy and collapse controls. The new-tab action is a small icon, with no dedicated row or fallback strip. The iframe fills the remaining fitted space; notes and URL editing remain one click away. Some destinations block embedding; the new-tab icon remains available. No invented metadata or remote scraping.
- Terminal uses a bundled xterm renderer with real local PTYs and OpenSSH in the desktop companion. Command/path completion, history, job control, interrupts, and full-screen programs come from the actual shell. Local project panes inherit that project's folder. A shared project selector filters the carousel without disconnecting hidden sessions; the rail supports left/right placement and five panes per page. Connection settings progressively disclose Local, SSH, or an existing HTTPS web terminal. Pane configuration persists; reload requires an explicit reconnect. The hosted static Site cannot open a shell on the visitor's computer and shows desktop setup instead. No commands, passwords, SSH private keys, or terminal transcripts are saved by Open Sesame.
- The interface uses subtle translucent glass, reflected borders, and restrained contrast. Persistent activity tabs share a compact top row with privacy and collapse controls; item search, capture classification, terminal connection settings, and secondary actions appear on demand. Lockin groups Music, Focus, YouTube, and Media; Items, Terminal, VNC, and Reading remain top-level tabs. Reduced motion, reduced transparency, and higher contrast preferences have explicit fallbacks.
- Reading is an embedded RSS 2.0/Atom viewer with feed subscriptions, refresh, compact fitted article pages, readable article content, Unread/All/Read later/Bookmarks collections, and explicit read/unread controls. Read later saves an article's original URL as a Bookmark in Items; removing it from Read later keeps that bookmark. Bookmarks also have a quiet Read later icon in their detail toolbar. Feed HTML is rebuilt from an allowlist without scripts, event handlers, images, or embedded content. Feeds without a full body show their supplied summary and original link. Articles longer than the bounded 12,000-character preview include a notice to continue in the original. A clearly labeled bundled sample feed is available without network access.
- Feed requests use credential-free browser fetch when permitted by the publisher's CORS policy, or a bounded native desktop request. The helper rejects credentials and non-HTTP URLs, verifies HTTPS normally, limits feeds to 2 MB, and permits up to three background retrievals without blocking terminal input. The reader keeps up to 20 feeds and 200 cached entries on this device. Read states and later states persist across refresh and reload. The existing 30-item capacity applies when saving new article links into Items.
- VNC adds saved named machines for a tailnet, local network, or another reachable network. Each machine accepts an HTTPS web VNC viewer URL, with embedded viewing, a device picker, disconnect, removal, external open, and fullscreen. noVNC viewer URLs use resize=scale and view_clip=false to fit the remote screen. Credentials are entered in the remote viewer itself. This static prototype does not discover devices, open raw TCP/VNC sockets, or provide a VNC/WebSocket gateway. The user’s browser must reach a configured gateway and that gateway must allow embedding.
- Console contains Coven Familiars, local process discovery, Shells, and Desktops. Connect Coven to discover its actual familiar roster, then choose a familiar and Send. Replies stream through the native CLI transport into separate saved conversations and drafts. Shell and Bash setup stay in Shells.
- Terminal → More → Live audio offers microphone, shared tab/system audio, or both. Capture begins only after an explicit Start click and browser permission. Web Audio mixes audio tracks, displays the actual input level, and optionally records audio for download. Stop, ended sharing, page exit, and a 30-minute limit release tracks and the audio context. Shared video is required by the browser picker but is never recorded.
- Browser speech recognition provides final/interim transcription where available. Shared-track recognition is enabled for desktop Chromium 135+, with microphone-only recognition available in other supporting browsers. Transcripts can be saved as notes, copied to the clipboard, or exported as text. Unsaved audio/transcripts stay in memory; saving a note uses local browser storage. Browser recognition may use its vendor's online speech service, as disclosed before starting.
- Screen-share privacy controls keep the widget visible locally. They open an explicit capability explanation, also available with Option/Alt + Shift + P. The browser prototype cannot exclude itself from another application’s screen capture; users can share a separate window/tab. Selective capture exclusion requires a native macOS implementation and verification with each sharing app. No protection state is simulated.
- M switches placement, E toggles expansion, Escape closes the URL editor/workspace or collapses the widget. Arrow keys navigate activity tabs and native sliders. Reset preserves items, projects, and the focus plan.

## Boundaries

The hosted Site is a browser prototype. The downloadable source includes a native AppKit menu-bar/notch host, WKWebView, folder picker, and local PTY/SSH bridge. It must be built and run on macOS to connect to that Mac. Music remains silent and notifications remain inside the widget. Items, projects, and settings are local to each browser or desktop app, not account-synced. Screen-share capture exclusion is not implemented in either host.

Private Sites hosting uses ChatGPT authentication. Coven Familiars uses the installed Coven CLI through the desktop or loopback development host. Connecting discovers identities; only an explicit Send invokes the familiar’s configured harness and provider account. Open Sesame does not install Coven or store model credentials. Static hosted pages display a desktop connection requirement.

Media capture requires HTTPS and browser/OS permission. Full system audio is offered only where the browser and OS support it; on a Mac, sharing a Chrome tab with Share audio enabled is the most portable option. The application rejects a shared stream with no audio instead of substituting the microphone. Unsupported speech recognition, denied permissions, and service errors are shown explicitly. No speaker identification is inferred from a mixed stream.
