# Tauri shell and new UI shell for the desktop restart

[open-sesame](src/lib.rs) is the Tauri 2 application of the restart in [epic #58](https://github.com/OpenCoven/open-sesame/issues/58): one window, a tray icon and one command. It is not shipped; the Swift host and Python bridge under [desktop](../desktop/AGENTS.md) remain the running application until the cutover. Read the root [instructions](../AGENTS.md) and the [core's instructions](../crates/AGENTS.md) first; the ownership, evidence, publication and prose rules there apply here.

The window label is not an isolation boundary. Any script in the main document can call the bridge, so the main window loads only this application's own files and no third-party script may ever be loaded there. The one reviewed exception to "this application's own files" is the terminal emulator described below, which is a bundled file from this repository and not a remote one. That rule is held in four places, and a change that loosens one needs a reviewed reason: the content security policy in [tauri.conf.json](tauri.conf.json) admits only bundled script; [the capability](capabilities/default.json) grants the main window alone and names no remote page; [window.rs](src/window.rs) refuses navigation away from the application's pages and refuses new windows; and [router.rs](src/router.rs) drops a request from any other window or page before the gate is even asked.

Terminal panes ([#74](https://github.com/OpenCoven/open-sesame/issues/74)) are split between the core and this crate. [The core's terminal module](../crates/core/src/terminal/mod.rs) owns the shell, the pseudo-terminal, the pacing and the kill; [terminal.rs](src/terminal.rs) here only joins a pane to a Tauri channel and holds the clipboard, and [project.rs](src/project.rs) holds the folder dialog and reveal. Output travels on one channel per pane as raw bytes, in order, followed by `terminal.exit`; it is never a window event. The page acknowledges what the emulator has parsed with `terminal.ack`, and the core stops reading from the shell when the page falls a megabyte behind, so a flood slows the program instead of filling memory. The clipboard, dialog and opener plugins are used from Rust only: the capability grants the page none of their commands, and it must stay that way.

The emulator is the reviewed xterm.js bundle in [dist/vendor](../dist/vendor/THIRD-PARTY.txt). It is not copied: `frontendDist` in [tauri.conf.json](tauri.conf.json) lists `../ui` and the two emulator files, so the application serves them as `./xterm.js` and `./xterm.css` beside the shell. Do not add a file of either name to `ui/`, and do not add another entry to that list without review, because every listed file becomes loadable by the main window. The emulator writes cell colours as style attributes, so the policy's `style-src` is `'self' 'unsafe-inline'`; `script-src` stays `'self'` and [check-tauri-bridge.mjs](../scripts/check-tauri-bridge.mjs) fails if `unsafe` appears anywhere else. Only the DOM renderer is bundled, so there is no renderer toggle.

A development build started with the `OPEN_SESAME_SELFTEST` environment variable set to a JSON object runs [ui/dev/selftest.js](../ui/dev/selftest.js), the launched-app acceptance pass for panes: a marker through the default shell, a folder with spaces and non-ASCII characters, a flood of numbered lines checked byte by byte while timer and frame gaps are measured, a pane closed over a long-running child, and three panes left open for Quit. It writes its report through a shell to the file named by `out`, and the script that started the app reads it, quits the app and checks that every recorded process is gone. A release build never sets the flag ([window.rs](src/window.rs)). The window belongs to the test while it runs: closing a tab by hand breaks the run, and such a run is not evidence.

[bridge_request](src/router.rs) is the only command. Do not add a second one: a new feature is a method on the wire protocol, admitted in the core's gate by the change that ports its handler. The command runs [gate::dispatch](../crates/core/src/gate.rs) first and then routes the allowed request to sign-in, to the window methods in [window.rs](src/window.rs), or to [Core::handle](../crates/core/src/handler.rs). [build.rs](build.rs) declares the command so that Tauri refuses it for any window the capability does not name. For a Windows build it also has the linker embed the application manifest in everything the package links and leaves Tauri's own copy out: Tauri's copy reaches the application binary only, and the library's test program does not start without one.

The main window is created in Rust in [window.rs](src/window.rs), not in the configuration, so the initialisation script sets `window.__OPEN_SESAME_NATIVE__` and `window.__OPEN_SESAME_VERSION__` before any page script runs. Closing the window hides it and keeps the page alive; the page must not load again when the window is shown. Quit is the tray's explicit action, and every way out ends in `RunEvent::Exit` in [lib.rs](src/lib.rs), which shuts the core down. The [tray](src/tray.rs) is a menu only, because Tauri's tray emits no click events on Linux.

The new UI shell is [ui/](../ui/index.html), chosen in [#61](https://github.com/OpenCoven/open-sesame/issues/61) in place of carrying `dist/` over. It is framework-free ES modules with relative imports, no build step and no npm runtime dependency, and it shares no global between modules. [bridge.js](../ui/bridge.js) is the transport: it uses the global `window.__TAURI__` object, sends `{requestId, method, params}` through the command and hands host events to subscribers. Views, the widget manifest and lazy loading belong to [#76](https://github.com/OpenCoven/open-sesame/issues/76); do not edit `dist/` for the restart.

Host messages go out through [events.rs](src/events.rs), addressed to the main window. The address is not what keeps them there: Tauri delivers an event sent to one window to any page listener registered without a target, in whichever window it is, and that is the kind `listen` on the global object registers. Only the capability does, by granting event listening to the main window alone. Do not grant `core:event:allow-listen` to another window unless that window may read every host message; [check-tauri-bridge.mjs](../scripts/check-tauri-bridge.mjs) pins the capability's exact permissions and windows for this reason.

Run `npm run dev:app` to start the application from the bundled files, which is the path a release build uses and the one the security policy applies to. Plain `cargo tauri dev` also works: the Tauri CLI then serves `ui/` from a loopback address with its own reload script, which a development build accepts and a release build never does, and the content security policy is not applied on that path. Both need the Tauri CLI, installed once with `cargo install tauri-cli --locked`.

Run `cargo fmt --all --check`, `cargo clippy --workspace --all-targets -- -D warnings` and `cargo test --workspace` from the repository root, then `npm run check`. The command's tests run on Tauri's windowless runtime and do not load the capability file; [check-tauri-bridge.mjs](../scripts/check-tauri-bridge.mjs) covers the transport against a fake window and reads the configuration, capability and shell files as text. Neither opens a window. A launched application is separate evidence, recorded per operating system: on macOS the tray menu cannot be opened by accessibility scripting, so hide, show and quit there are driven through the close button, the Dock icon and the application menu unless a person clicks the tray.
