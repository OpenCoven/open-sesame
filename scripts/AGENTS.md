# Checks, builds and local task tooling

Run scripts from the repository root unless their help says otherwise. Read [development workflow](../docs/development-workflow.md) and the [repository map](../docs/repository-map.md) before changing checks. Keep original failures and per-run receipts; do not widen deadlines, skip prerequisites or weaken PTY/origin/cleanup assertions to make a candidate pass.

[check.mjs](check.mjs) discovers root-level `check-*.mjs` scripts, gives each a 30-second limit and checks authored JavaScript syntax. A new behavioral check in that pattern joins `npm run check` automatically; helper modules must use a different filename. Native `check-*.sh` scripts and Python suites are selected explicitly by [verify.py](verify.py). The standalone documentation check is [check-docs.mjs](check-docs.mjs), exposed as `npm run check:docs`; it validates repository-local Markdown navigation without contacting external services.

[verify.py](verify.py) runs checks through [run_bounded.py](run_bounded.py), records logs/commands/cleanup under `build/verification/<UTC>/`, compares source archives, and verifies the final source fingerprint. Mac scope includes native checks and bundle compilation/signature/plist/icon; `--portable` explicitly omits native scope. Run one verifier at a time per worktree and make no source edits during it. A timeout, unknown cleanup state or leftover owned helper is a failure. The [tooling tests](tests/) exercise watchdog, source-archive and worktree guards; [desktop/tests](../desktop/tests/) contains application adapters and PTYs.

[project.py](project.py) owns local task claims, inventory, REST refresh and guarded retirement through the npm project commands. Resolve shared records with `git rev-parse --git-common-dir`; source docs are not locks or owner-release records. Never mutate another task's state, forge a remote snapshot or broaden cleanup targets. [build-desktop-source.py](build-desktop-source.py) and [distribution_safety.py](distribution_safety.py) keep private data out of deterministic source packages. Preserve executable fixture modes, licenses and pinned upstream provenance. Source packages must include package-lock.json and the versioned .githooks files so documented setup remains reproducible.

For rendered layout, inspect [fixtures/widget-fit.html](fixtures/widget-fit.html) and [its harness](fixtures/widget-fit.js). It loads actual authored UI with synthetic host responses; no live provider, capture or shell is available. Serve it through an explicitly loopback-bound static server from the repo root, choose an unused port, and stop only the server this task owns. Example: `python3 -m http.server 4189 --bind 127.0.0.1`, then open `/scripts/fixtures/widget-fit.html`. Do not expose the repository server publicly or terminate a process already using the port. This is distinct from the sign-in-only `npm run dev` server and from native/device acceptance.

[check-secrets.py](check-secrets.py) scans staged paths/content; [install-hooks.py](install-hooks.py) configures the current worktree after preserving custom hook paths. Follow [the setup contract](../docs/development-workflow.md#pre-commit-secret-checks); do not bypass a failed hook or weaken scanner coverage. Optional [VNC browser fixtures](fixtures/vnc-browser.mjs) use pinned npm development dependencies and Chromium, while core checks remain dependency-free.

Markdown tokenizer changes require [check-markdown-redos.mjs](check-markdown-redos.mjs): bounded source/runtime adversarial workers, syntax/render regressions and an exact temporary rebuild comparison. [build-markdown.mjs](build-markdown.mjs) accepts an optional output file so checks never rewrite tracked runtime assets. Keep upstream licenses/provenance and local patch notices aligned.

The optional [mobile browser fixture](fixtures/mobile-browser.mjs) blocks external requests and qualifies the authored renderer with synthetic items in Chromium/WebKit. It requires an owned loopback static server and must not be used as device or native acceptance; see the [mobile check contract](../docs/mobile-shell.md#checks).

[Mobile transport lifecycle](fixtures/mobile-transport.mjs) substitutes only the test transport while retaining real xterm/Coven client/UI owners; [mobile pane layout](fixtures/mobile-pane-layout.mjs) checks narrow Projects editing/Back and large text. Both use the same owned loopback fixture server and must remain explicitly synthetic. Do not turn their in-memory responses into production capability or identity state.

[Mobile visual checks](fixtures/mobile-visual.mjs) compare reference-derived presentation with real production models and poisoned prototype storage. Keep prototype content confined to fixtures and the independently owned reference; do not weaken real-client/navigation assertions to obtain a visual pass.

[Mobile installed forms](fixtures/mobile-forms.mjs) exercise real page adapters, configuration persistence and canonical local note/task writes. Respect item limits by archiving fixture notes through their owner. In mobile Task Manager, the page view owns scrolling; retain a real nonzero page scroll and exact return-position assertion rather than assuming a nested list scrolls.

[Mobile built-in interiors](fixtures/mobile-interiors.mjs) exercise scheduling, editor Tab containment, cached Reader pagination/scroll and Tools install/dismissal using real owners and blocked external requests. Keep original failures, independent per-area results and explicit font/pointer/focus checks; do not replace canonical writes with DOM-only stubs.

[review-content-focus.mjs](review-content-focus.mjs) renders the authored interface with disposable synthetic host, clipboard, terminal, reading and familiar state. It checks retained content and interactions across view changes; it does not type into a real shell, read the user clipboard or send a model prompt. Keep these limits explicit when reporting its evidence.
