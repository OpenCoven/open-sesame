# Widget and launcher fit repair

The v0.0.16 GitHub monitor reused `window.OpenSesameGitHub`, which already belonged to the repository preview used by Projects and widget rendering. Replacing its `render` and `isRepo` methods could interrupt rendering before the native window received its expanded dimensions, leaving full content clipped into the initial compact frame. The monitor now owns `window.OpenSesameGitHubMonitor` and `github-monitor-*` control IDs; the existing preview API and controls remain intact. The duplicate `github-back` ID is removed.

The widget commits native shell dimensions before pane-specific content rendering, so a pane exception cannot leave the window at an old compact size. The integration regression loads both shipped GitHub modules, exercises the actual bookmark preview and native size functions, and requires the 800 × 450 expanded request. Another regression preserves an intentionally thrown pane failure while verifying that native sizing already happened. The original API collision and ordering failures are retained in task receipts.

The launcher footer and calculation surface now use the same interpreted capture intent as command execution. A bare `/`, a slash command, a Bash draft or a literal capture type cannot retain a calculation card or disable the command action as “Finish calculation.” Valid calculations, including a zero result, still work; invalid calculations remain uncopyable. This keeps displayed output, the action label and Enter behavior consistent.

Command rows explicitly stack a 16 px title line and a 13 px description line with a 2 px gap inside a 46 px row. The icon and shortcut align to the row center, long text truncates within its own column, and narrow layouts retain that structure. Only the results container scrolls; the command list has no nested overflow region. The search header and action footer retain their space, with compact variants for short windows.

Open `scripts/fixtures/widget-fit.html` through a loopback static server for an isolated rendered review. It loads the authored application into a synthetic native viewport and exposes launcher, slash, zero calculation, Focus, collapse and small-display controls. The fixture has no real machine bridge, account, model or recording capability. It is a manual layout aid, not native/device acceptance. In this session the browser host was unavailable and native inspection timed out; automated source/behavior checks, compilation and actual installed rendering must remain separate evidence.
