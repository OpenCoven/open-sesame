# Widget and launcher fit repair

The v0.0.16 GitHub monitor reused `window.OpenSesameGitHub`, which already belonged to the repository preview used by Projects and widget rendering. Replacing its `render` and `isRepo` methods could interrupt rendering before the native window received its expanded dimensions, leaving full content clipped into the initial compact frame. The monitor now owns `window.OpenSesameGitHubMonitor` and `github-monitor-*` control IDs; the existing preview API and controls remain intact. The duplicate `github-back` ID is removed.

The widget commits native shell dimensions before pane-specific content rendering, so a pane exception cannot leave the window at an old compact size. The integration regression loads both shipped GitHub modules, exercises the actual bookmark preview and native size functions, and requires the 800 × 450 expanded request. Another regression preserves an intentionally thrown pane failure while verifying that native sizing already happened. The original API collision and ordering failures are retained in task receipts.

The launcher footer and calculation surface now use the same interpreted capture intent as command execution. A bare `/`, a slash command, a Bash draft or a literal capture type cannot retain a calculation card or disable the command action as “Finish calculation.” Valid calculations, including a zero result, still work; invalid calculations remain uncopyable. This keeps displayed output, the action label and Enter behavior consistent.

Command rows explicitly stack a 16 px title line and a 13 px description line with a 2 px gap inside a 46 px row. The icon and shortcut align to the row center, long text truncates within its own column, and narrow layouts retain that structure. Only the results container scrolls; the command list has no nested overflow region. The search header and action footer retain their space, with compact variants for short windows.

Open `scripts/fixtures/widget-fit.html` through a loopback static server for an isolated rendered review. It loads the authored application into a synthetic native viewport and exposes launcher, slash, zero calculation, Focus, collapse and small-display controls. The fixture has no real machine bridge, account, model or recording capability. It is a manual layout aid, not native/device acceptance. After the browser host failed, native Safari access recovered. The authored WebKit fixture was observed with aligned slash rows, a zero-valued calculation, a footer at the bottom of a 760 × 500 launcher, a complete 800 × 450 workspace, a 280 × 35 compact widget, and a 366 × 256 launcher with a visible header/footer and one results scroller. These are rendered fixture observations; installed native acceptance is separate.


The Live shortcut editor is now a centered, bounded dialog instead of an edge popover. It offers a first-use creation flow without a redundant selector, switches to edit labels for saved questions, previews the normalized slash command, counts question characters and disables an empty save. Cancel and Escape preserve the saved question; saving only updates local shortcut storage and never invokes an agent or starts capture. The Shortcuts entry is available before transcription starts. Collapse, launcher entry and leaving Live dismiss the editor without leaving a modal over the compact widget.

Native widget entry and the menu-bar toggle use the same renderer state transitions. Open widget exits the palette into the workspace; close/collapse retires palette state before requesting compact dimensions. Drafts, PTYs and ongoing audio remain in the existing web view. The native web view is pinned to all four content edges, and the renderer has an opaque dark background in every state. This addresses the reported compact audio chip inside an oversized blank window without reloading or clearing active work.

The exact supplied gold emblem is kept in `dist/assets/open-sesame-logo.png`. The macOS build creates all ten standard/Retina ICNS representations and declares the icon in the bundle plist; the application, menu bar, sign-in and web branding use the same art. A packaged-icon check validates the actual resources, representations and stable bundle identity. No new permissions or account settings are needed.
