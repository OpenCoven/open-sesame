# Repository map for agents

This map follows the current source layout. Run commands from the repository root unless a command says otherwise. Read the [root instructions](../AGENTS.md), inspect the [current task state](work-tracking.md#find-current-work), and use an isolated owned worktree before editing. The [documentation index](README.md) routes feature questions; the [capability matrix](capabilities.md) keeps implementation and acceptance separate.

## Entrypoints and host boundaries

| Surface | Entrypoints | Boundary |
| --- | --- | --- |
| Browser workspace | [dist/index.html](../dist/index.html), [app.js](../dist/app.js) | Ordered deferred scripts share globals and the DOM; this is authored source, without a framework build step |
| Renderer RPC | [bridge.js](../dist/bridge.js) | Request IDs, pending replies, timeouts and native events; a browser flag or dormant WebSocket fallback does not enable a machine host |
| Native host | [OpenSesame.swift](../desktop/OpenSesame.swift), [Authentication.swift](../desktop/Authentication.swift) | Login gates widget/bridge startup; trusted main-frame file origin and per-method checks gate requests |
| Python service | [bridge.py](../desktop/bridge.py) | Native stdio carries JSON lines; dispatches PTYs and approved adapters, emits replies/events and closes owned jobs |
| Embedded provider content | [EmbeddedWebSurface.swift](../desktop/EmbeddedWebSurface.swift), [native-surfaces.js](../dist/native-surfaces.js) | Separate WKWebViews; external pages do not inherit application RPC; YouTube uses its restricted player event channel |
| Loopback preview | [dev_server.py](../desktop/dev_server.py) | `npm run dev` serves sign-in/downloads, refuses the machine WebSocket route and never starts a shell |
| Public login handoff | [worker.mjs](../web/auth-entrypoint/worker.mjs), [build.mjs](../web/auth-entrypoint/build.mjs) | Fixed HTTPS-to-native login initiation; no provider code exchange, private download or machine endpoint |
| Consumer example | [coven_familiars.py](../examples/coven_familiars.py) | Reuses the actual adapter; listing is metadata, `--message` explicitly invokes a real provider |

Trace a bridged operation from its renderer caller through [bridge.js](../dist/bridge.js), the authenticated origin/method router in [OpenSesame.swift](../desktop/OpenSesame.swift), and [Bridge.handle](../desktop/bridge.py) to its adapter. Responses return by request ID; streaming output returns as events. Window, speech, recording, screen capture, native VNC and native Spotify operations are handled in Swift rather than automatically delegated to Python. Changes to a public operation must update both the receiving route and its caller/checks without widening unrelated permissions.

`github-viewer.js` renders repository previews; `github-monitor.js` owns the authenticated monitor. Their distinct globals and element IDs are intentional. New packages use schemaVersion 2 with a required destination page; legacy v1 packages stay under Widgets. [page-widgets.js](../dist/page-widgets.js) adds installed tabs while preserving mounted native content, and [application-chrome.js](../dist/application-chrome.js) owns the detached/full application header. See [page/window contracts](widget-pages-and-application.md). Global-script ordering and CSS cascade ordering in `index.html` are part of the runtime contract. New globals and IDs must not shadow existing features. Use `rg` for a selector, global or bridge method before introducing another one.

## UI names and internal keys

The UI says **Widgets**, **Console**, **Live**, **Projects** and **Focus**. Existing code/state may call those `plugins`, `agents`, `audio`, `items` and `lockin` respectively. Keep compatibility keys separate from user-facing wording. Focus uses scenario `focus` and activity key `lockin`; Media scenarios (`music`, `youtube`, `media`) use activity key `entertainment`. A package page ID such as `focus` or `projects` is a separate contract from those legacy activity keys. The built-in connection catalog, page adapters, declarative package host and floating application have distinct lifecycles even when older docs call all of them widgets.

## State and provenance

| Data | Owner and location | Change boundary |
| --- | --- | --- |
| Browser/workspace settings, saved items and tool instances | Device-local website storage; [storage-migration.js](../dist/storage-migration.js), feature models and host snapshot/handoff code | Preserve existing keys, IDs and drafts; the native bundle identifier remains `com.perch.widgetstudio` for compatibility |
| Familiar conversations and GitHub monitor preferences | [state_directory](../desktop/coven_runtime.py) and [GitHubMonitor](../desktop/github_monitor.py): app-specific Application Support on Mac, XDG data fallback elsewhere | Use isolated fixture directories in checks; do not inspect private history or reset preferences as an audit shortcut |
| Authentication | Native [Keychain session](../desktop/Authentication.swift); Spotify native tokens remain in memory | Never put tokens, callback data or provider error bodies in the renderer, logs, fixtures or source downloads |
| VNC profiles and credentials | [remote.js](../dist/remote.js) saves metadata; [VNCTransport.swift](../desktop/VNCTransport.swift) optionally stores credentials in Keychain | Keep plaintext passwords out of profiles/exports; session authentication inputs are transient |
| Task ownership and delivery receipts | Common Git directory → `open-sesame/tasks`, `receipts`, `remote.json` | Find with `git rev-parse --git-common-dir`; this is shared by worktrees and excluded from source packages |
| Generated output | `build/`, `dist/downloads/`, `web/auth-entrypoint/dist/`, caches | These are distinct from authored `dist/`; never blanket-clean another owner's outputs |
| Third-party source and bundles | [vendor-src](../vendor-src/), [dist/vendor](../dist/vendor/), [vendor notices](../dist/vendor/THIRD-PARTY.txt) | Preserve licenses and provenance; Markdown and WorkOS builders verify/use pinned sources |

## Repository safeguards

[The versioned pre-commit hook](../.githooks/pre-commit) invokes [check-secrets.py](../scripts/check-secrets.py) on staged content. [install-hooks.py](../scripts/install-hooks.py) installs a worktree-local hook path while preserving custom paths; it also enables the shared Git worktree-config extension. Install the documented Gitleaks prerequisite and inspect the existing hook configuration before committing. [Secret-hook tests](../scripts/tests/test_secret_hook.py) use fixtures rather than real credentials. See [the workflow](development-workflow.md#pre-commit-secret-checks) for limitations and failure handling.

## Verification and delivery route

For a focused JavaScript check, run `node scripts/check-NAME.mjs`. For a focused Python module, use its discoverable file pattern, for example `python3 -B -m unittest discover -s desktop/tests -p 'test_github_monitor.py' -v`. Native Swift test scripts compile synthetic checks; they do not require an actual provider login. [scripts/AGENTS.md](../scripts/AGENTS.md) describes discovery and the bounded runner. [desktop/AGENTS.md](../desktop/AGENTS.md) describes the native boundary and prerequisites.

`npm run check` includes the documentation navigation check. Run `npm run verify` for Mac scope or `npm run verify -- --portable` for explicit portable scope. Run only one verifier per worktree and freeze source during a run; the final fingerprint must match. See [development workflow](development-workflow.md#implement--verify--review) for evidence, and the actual [CI workflow](../.github/workflows/verify.yml) for selected versions and trigger conditions.

[build-desktop-source.py](../scripts/build-desktop-source.py) writes the reproducible source archive, including the lockfile and versioned hooks; [build-macos.sh](../desktop/build-macos.sh) replaces the development bundle under `build/` without launching it. `npm run dev:macos` additionally opens that bundle. [The public auth build](../web/auth-entrypoint/build.mjs) writes only its dedicated generated web output. None of these commands installs to Applications, publishes a release, configures a domain or proves live acceptance. Follow the user's actual delivery authority.
