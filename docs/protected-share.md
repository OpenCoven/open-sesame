# Protected Share in the installed Mac app

Open Sesame stays visible locally and creates an optional share window whose ScreenCaptureKit input excludes Open Sesame's process. In the widget's menu choose Screen-share privacy, or use Option–Shift–P while the widget is focused. Choose the display you intend to share and click Start protected share. Allow macOS Screen & System Audio Recording permission if requested. In Google Meet choose Present now → A window → **Open Sesame — Protected Share**; check Meet's preview before presenting and leave that window open. Stop in Open Sesame or close the output window when finished. Do not select Your entire screen if you need the widget excluded.

This is a filtered output workflow, not a global invisible-window flag. Apple's current documentation calls [`NSWindow.SharingType.none`](https://developer.apple.com/documentation/appkit/nswindow/sharingtype-swift.enum/none) a legacy constant that macOS no longer uses. Open Sesame therefore uses the public [`SCContentFilter(display:excludingApplications:exceptingWindows:)`](https://developer.apple.com/documentation/screencapturekit/sccontentfilter/init(display:excludingapplications:exceptingwindows:)) API to exclude its current process from its own video stream. Apple demonstrates this filtering pattern in its [screen-capture sample](https://developer.apple.com/documentation/screencapturekit/capturing-screen-content-in-macos). Open Sesame cannot change another application's full-display capture filter or hide visible content from a person physically looking at the monitor.

Capture never starts during launch, privacy status reads, opening the information dialog, or synthetic tests. Only an authenticated explicit Start action can request ScreenCaptureKit access. Native start validates the selected current display and verifies the current process is in the exclusion list before constructing the stream. There are no excepted windows. The stream captures video only, up to 2560 pixels on the longest edge at 15 frames per second, without audio, files, uploads or telemetry. The meeting application controls its own transmission. Protected Share is not a remote-control surface.

The output starts black and is marked ready only after a complete video frame from the filtered stream arrives. Invalid/incomplete frames are refused. A bounded latest-frame slot and renderer backpressure prevent unbounded frame retention. Stop, close, sign-out, display configuration change or stream failure invalidates pending callbacks, hides/clears the output and closes its window; stream capture is stopped asynchronously. Cancelling preparation invalidates its generation so delayed permission or stream completion cannot reactivate capture. Display changes require a fresh explicit Start. A ten-second first-frame timeout clears an unusable output. No raw provider/system error payloads or image contents enter logs.

Native tests use synthetic pixel buffers and completeness metadata, cancellation/stale-generation checks, concurrent frame producers, backpressure and invalid-display refusal. Renderer tests cover status-only initialization, explicit selected-display start, cancellation while permissions are pending, stale replies, failures, disconnects and the Google Meet instructions. These checks do not request permission, capture a physical screen, start a call or establish recipient-side privacy. The public API is implemented, but live acceptance remains open until the selected Meet preview is observed.

For device acceptance, start the installed app's output on each intended display, place a distinctive local-only marker inside the widget and a different marker in a separate app, then confirm the widget marker is absent and the other marker remains in the Protected Share output and Meet's recipient preview. Exercise collapse, expansion, pointer following and detached placement while sharing. Verify Stop/close/sign-out blanks or ends output, display removal stops it, denied permission never produces a ready state, and late callbacks after cancellation do not restore video. Do not publish screenshots or recordings containing real workspace content as test artifacts. A successful compile, local output or selected-window label alone is not recipient acceptance.
