# System audio detection and transcription

In Live choose Transcribe and System audio, then Start. Use Microphone + system audio only when both sources are wanted. The native app requests macOS Speech Recognition and Screen & System Audio Recording permission after Start; system-only capture leaves the microphone off. Audio from the Mac is normalized to uncompressed 48 kHz mono PCM and appended to the native speech request. Apple's [PCM input contract](https://developer.apple.com/documentation/speech/sfspeechaudiobufferrecognitionrequest/append(_:)) and [ScreenCaptureKit audio output](https://developer.apple.com/documentation/screencapturekit/scstreamoutputtype/audio) describe these interfaces. The app prefers on-device recognition when supported; permission, installed language support and the OS speech service remain live requirements.

The previous clock started before awaiting capture initialization. A synthetic four-second startup delay placed every incoming chunk four seconds ahead of the reader in a three-second ring; 200 non-silent input chunks produced zero audible output chunks indefinitely. The repair starts and resets the timeline only after native capture succeeds, and rejects samples received before that origin. The bounded ring and stale/future sample guards remain intact. Delays of zero, four and 120 seconds now preserve every tested chunk. The reproduction and original failing receipt are retained in common Git storage under `system-audio-transcription-20261108`.

During native system or mixed capture, the status distinguishes Waiting for system audio, System audio is silent and System audio detected. The combined source reports microphone activity independently, so speaking into the microphone cannot falsely indicate system audio. A short activity hold avoids flickering between words, and absent packets expire back to waiting. These labels describe PCM energy reaching the capture pipeline, not speech-recognition success. Transcript status changes to Transcribing live when text actually arrives. No detection or capture begins before Start, and no permission or microphone access is requested by opening Live or reading status.

Synthetic native tests exercise delayed start, pre-start rejection, mixed signal isolation, silence/stale activity, independent PCM copies and real interleaved/planar stereo resampling from 44.1 kHz to the speech format. Renderer regressions exercise all three native sources, activity bound to current capture IDs, recording feedback, stop protection and transcript handoff. They capture no hardware audio and invoke no speech provider. Native hardware playback, macOS permission prompts, real system-only and mixed transcription, exports and speech-service behavior remain separate device acceptance checks.
