# Embedded Coven computer agent

## Start a task

Open Console → Computer, choose an account, and describe the task. `/computer …` and reviewed voice requests open this same view; they do not start a terminal or perform an action. Familiar conversations, local shells and the simple volume/mute/app controls retain their separate behavior.

Choose Coven default account to use the configured image-capable Anthropic or Codex provider, or Coven Codex account to select an already connected Codex account without changing global Coven settings. Anthropic API can use a key entered through Account → Connect Anthropic API. That native secure field saves only this app's own Mac Keychain item. Remove saved API key removes that item, preserving Coven accounts. Keys never enter WebKit, tool packages, chat messages or exported task text. Setup checks configuration; a completed live turn is needed to establish actual provider/model access. This release does not add a new ChatGPT OAuth client or claim subscription entitlement; a future app-owned connection must follow the [official registration flow](https://developers.openai.com/siwc/token-sharing-open-source/sign-in).

On macOS 14 or later, explicitly enable Screen Recording and Accessibility for Open Sesame, then refresh. Review & start opens a native confirmation for the exact task, provider/model and chosen display. Cancel keeps the draft. Approval permits screenshots to that provider and serial input on that display for this task, for up to ten minutes. Connecting an account or reviewing a task never sends a model request or captures the screen.

Use the mouse or keyboard to pause. Stop task is available in Console and in the menu-bar menu while a task or approval is active. Stop revokes pending actions and terminates only the owned engine; it cannot undo completed changes. When the agent asks a question or reaches a boundary, review the screen and enter the next instruction to start a newly confirmed task. Text history stays in the current application view; screenshots and keys are excluded. Reload/sign-out ends the task and retires that view's text history. Task text is not a replacement for saving work in the applications being used.

## Engine and native boundary

The build compiles a standalone engine from pinned Coven core/provider libraries and Open Sesame's orchestration. The original GPL-3.0 source archive, license and digest are retained in [vendor-src/coven-engine](../vendor-src/coven-engine/README.md). No dirty upstream checkout is used. The builder verifies all 815 upstream source files and refuses a changed cache, then binds the binary receipt to source, Cargo.lock, adapter files, compiler and build settings. The app bundles that binary and a distinct CovenEngine-BUILD-INFO.json receipt. Rust/Cargo and dependency download access are build prerequisites; the installed runtime uses the bundled binary and Python 3.

The engine exposes one application-owned computer tool, with observe, click/double/right click, move, drag, Unicode typing, supported key combinations, scroll, wait and ask_user. No shell, filesystem, plugin, MCP or delegated-agent registry is attached. The pinned Coven SDK supplies typed image/tool messages and streaming. A reply must finish cleanly, with exactly one permitted tool call, before native dispatch. The engine keeps at most four screen images in context and bounds turns, actions, stream size and elapsed time.

A per-run authenticated loopback channel connects the engine to the native host. Origin/host/path/content-length checks, a private bearer token, single-use native reply identities and a native-only session nonce exclude renderer and foreign-origin callers. Swift intercepts all private action/proposal/completion traffic before forwarding public progress to WebKit. Browser previews have no machine host. The approved provider/model and route binding are checked again before execution; account changes invalidate pending proposals.

Selected-display screenshots exclude Open Sesame itself and contain no audio. Actual image dimensions map to the display's Quartz bounds, including offset displays. Every input consumes a recent observation ID, and the host checks current run, display geometry, foreground application, human interaction generation, bounds and cancellation again before dispatch. Focus/display changes during capture are refused. Keyboard dispatch additionally binds the same accessibility control and bounds before each event, refuses secure text fields, and requires the target to fit within the approved display. Scroll events use a point on that display, optionally supplied by the model, instead of the user’s unrelated pointer location. Native mouse/key events are marked to distinguish the agent's own input from the user's. Human input pauses the task; cancellation releases an owned drag button and revokes outstanding work. Key shortcuts use a finite mapping; Unicode text uses scalar-safe UTF-16 chunks.

Screens and model responses are untrusted task data. The system instruction requires handoff for passwords/CAPTCHA, confirmation for consequential sends/deletion/financial/legal/security changes, and refusal to run shell/scripts through application UIs. These are model instructions alongside native run/action constraints; they are not a proof that a model will identify every sensitive action. The native dialog describes the actual ability to change files and transmit information. Use a concrete, limited task and supervise it.

## Verification and remaining acceptance

Focused checks exercise the real Coven Anthropic streaming adapter against local HTTP/SSE fixtures, typed image/geometry round trips, truncated-stream refusal, screenshot retirement, private broker authentication and one-time replies, approval expiry, startup/cancellation/reaping, preservation of an unrelated process, renderer/native route isolation, UI early/late events and Stop races, offset geometry/freshness, supported keys, and JPEG encoding of a generated image within the stdio budget. No actual user screen, model account request, permission grant, Keychain write or input action is used by those checks.

`npm run verify` adds bounded engine build and release-mode tests to Mac scope, alongside the existing real-PTY, origin/cleanup, source archive, Swift, authentication and signature checks. `--portable` retains Python/JavaScript and source packaging checks and explicitly omits native/engine compilation. A synthetic browser preview demonstrates layout only. Native confirmation/input/human pause, actual selected-display capture, live provider access and a supervised end-to-end task on the installed release remain distinct device/provider acceptance gates until observed; compilation, source merge and fixtures do not establish those results. No Windows/Linux packaged computer-use host is qualified.
