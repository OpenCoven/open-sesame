# Embedded Coven computer agent

## Start a task

Open Console → Computer, choose an account, and describe the task. `/computer …` and reviewed voice requests open this same view; they do not start a terminal or perform an action. Familiar conversations, local shells and the simple volume/mute/app controls retain their separate behavior.

Use **Codex · ChatGPT** to sign in with the official Codex CLI’s ChatGPT browser flow, or **Claude Code** for Claude CLI subscription sign-in. Sign in opens a fixed login command in a temporary in-app Shell. Finish the provider’s browser flow yourself; when the command exits, the app verifies authentication metadata and returns to Computer if that login pane is still selected. It preserves your task draft and never starts the task automatically. A failed or incomplete login stays visible for recovery. Connected accounts show their status instead of offering redundant sign-in; temporary login commands are not saved as reusable shell panes. No API-key entry, Anthropic API client, token import or custom OAuth client is used. Status runs only CLI authentication metadata commands and rejects API-key, helper and third-party authentication modes. Existing app Keychain items are left untouched and unused.

Choose **Coven Familiar**, select a familiar from the fresh Coven roster, and choose its signed-in Codex or Claude account. That familiar drives the approved native computer task with its name, role and workspace identity. The native confirmation names the familiar, workspace and account destination; changed identity or CLI route invalidates approval. This context does not import the familiar’s persistent chat history or grant filesystem access to its workspace. Computer task histories are separated by driver in the current application view. CLI account/model access and a supervised live task remain provider acceptance gates; checking sign-in does not send a model request.

On macOS 14 or later, explicitly enable Screen Recording and Accessibility for Open Sesame, then refresh. Review & start opens a native confirmation for the exact task, provider/model and chosen display. Cancel keeps the draft. Approval permits screenshots to that provider and serial input on that display for this task, for up to ten minutes. Connecting an account or reviewing a task never sends a model request or captures the screen.

Use the mouse or keyboard to pause. Stop task is available in Console and in the menu-bar menu while a task or approval is active. Stop revokes pending actions and terminates only the owned engine; it cannot undo completed changes. When the agent asks a question or reaches a boundary, review the screen and enter the next instruction to start a newly confirmed task. Text history stays in the current application view; screenshots and keys are excluded. Reload/sign-out ends the task and retires that view's text history. Task text is not a replacement for saving work in the applications being used.

## Engine and native boundary

The build compiles a standalone engine from pinned Coven core message types and Open Sesame's orchestration. The original GPL-3.0 source archive, license and digest are retained in [vendor-src/coven-engine](../vendor-src/coven-engine/README.md). No dirty upstream checkout is used. The builder verifies all 815 upstream source files and refuses a changed cache, then binds the binary receipt to source, Cargo.lock, adapter files, compiler and build settings. The app bundles that binary and a distinct CovenEngine-BUILD-INFO.json receipt. Rust/Cargo and dependency download access are build prerequisites; the installed runtime uses the bundled binary and Python 3.

The engine exposes one application-owned computer tool, with observe, click/double/right click, move, drag, Unicode typing, supported key combinations, scroll, wait and ask_user. No shell, filesystem, plugin, MCP or delegated-agent registry is attached. Pinned Coven core types preserve image, tool-call and tool-result pairing. An account-owned CLI returns one completed JSON plan through the private broker. Codex runs ephemeral with ignored user configuration, read-only sandbox, no web/MCP configuration, and disabled shell, image tools, hooks, apps, multi-agent, remote plugins and image generation; any CLI tool event is refused. Claude runs with safe/restricted mode, no built-in tools, strict empty MCP, disabled hooks/skills and no persisted session. Only a successful completed structured result is admitted before the native action validator. No provider credentials leave the official CLI. The engine keeps at most four screen images in context and bounds turns, actions, stream size and elapsed time.

A per-run authenticated loopback channel connects the engine to the native host. Origin/host/path/content-length checks, a private bearer token, single-use native reply identities and a native-only session nonce exclude renderer and foreign-origin callers. Swift intercepts all private action/proposal/completion traffic before forwarding public progress to WebKit. Browser previews have no machine host. The approved provider/model and route binding are checked again before execution; account changes invalidate pending proposals.

Selected-display screenshots exclude Open Sesame itself and contain no audio. Actual image dimensions map to the display's Quartz bounds, including offset displays. Every input consumes a recent observation ID, and the host checks current run, display geometry, foreground application, human interaction generation, bounds and cancellation again before dispatch. Focus/display changes during capture are refused. Keyboard dispatch additionally binds the same accessibility control and bounds before each event, refuses secure text fields, and requires the target to fit within the approved display. Scroll events use a point on that display, optionally supplied by the model, instead of the user’s unrelated pointer location. Mouse movement, clicks, drags and scrolling use a separate gold Agent pointer and process-targeted events bound to the observed target window; they do not post global mouse events or move the physical pointer. The target app can become active for a click. Apps or system gestures that reject targeted events require user handoff; there is no physical-pointer fallback. Keyboard input still uses the shared focused control. Native mouse/key events are marked to distinguish the agent's own input from the user's. Human input pauses the task; cancellation releases an owned drag button and revokes outstanding work. Key shortcuts use a finite mapping; Unicode text uses scalar-safe UTF-16 chunks.

Screens and model responses are untrusted task data. The system instruction requires handoff for passwords/CAPTCHA, confirmation for consequential sends/deletion/financial/legal/security changes, and refusal to run shell/scripts through application UIs. These are model instructions alongside native run/action constraints; they are not a proof that a model will identify every sensitive action. The native dialog describes the actual ability to change files and transmit information. Use a concrete, limited task and supervise it.

## Verification and remaining acceptance

Focused checks exercise the account-owned CLI argument/input/output fixtures and private local HTTP planner fixtures, typed image/geometry round trips, truncated-plan refusal, screenshot retirement, private broker authentication and one-time replies, approval expiry, startup/cancellation/reaping, preservation of an unrelated process, renderer/native route isolation, UI early/late events and Stop races, offset geometry/freshness, pointer window selection and event metadata without posting input, login completion/draft handoff, supported keys, and JPEG encoding of a generated image within the stdio budget. No actual user screen, model account request, permission grant, Keychain write or input action is used by those checks.

`npm run verify` adds bounded engine build and release-mode tests to Mac scope, alongside the existing real-PTY, origin/cleanup, source archive, Swift, authentication and signature checks. `--portable` retains Python/JavaScript and source packaging checks and explicitly omits native/engine compilation. A synthetic browser preview demonstrates layout only. Native confirmation/input/human pause, actual selected-display capture, live provider access and a supervised end-to-end task on the installed release remain distinct device/provider acceptance gates until observed; compilation, source merge and fixtures do not establish those results. No Windows/Linux packaged computer-use host is qualified.

## Review refinements

The CLI planner explicitly disables the known Codex shell, browser, computer, local automation, code execution, plugin and skill capabilities as well as MCP and hooks. Completed tool events are rejected before admitting a plan. These launch constraints and output checks are covered by executable fixture CLIs; they do not establish future CLI tool registries or live provider behavior. Both planners retain ordinal screenshot references beside observation geometry. Stop publishes terminal progress for native-only cancellation paths, and questions are retained in the text history used for a newly approved continuation.

Account approval hashes public Claude account/organization metadata and the official Codex credential file’s filesystem identity and timestamps without reading its contents. A token refresh or file replacement also invalidates the Codex route, requiring renewed review. Missing identity metadata fails closed. A native session cancellation remains revoked while startup metadata is being checked. CLI group cleanup keeps the direct child unreaped until its helpers have exited; leftover helpers invalidate a completed plan.
