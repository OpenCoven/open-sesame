# Restart default views: Today, Projects and Focus

[Issue 77](https://github.com/OpenCoven/open-sesame/issues/77) ports the three views a fresh install opens with onto the [ES-module shell](ui-shell.md) and the restart's local storage. They replace only the `today`, `projects` and `focus` entries in [widget-loaders.js](../ui/widget-loaders.js) and share one stylesheet, [views.css](../ui/widgets/views.css). Each view keeps the shell's lifetime contract: it mounts into its own surface, stops at its AbortSignal, adds no global, uses no browser storage and calls no new host method.

## Views

[Today](../ui/widgets/today.js) follows the mobile presentation's Today overlay ([mobile-shell.md](mobile-shell.md)): quick capture of a note or a task, the latest active note with its excerpt and project, the focus clock, and the open and completed task counts with up to three open tasks to complete in place. [Projects](../ui/widgets/projects.js) lists notes, tasks and bookmarks together, filtered by project, kind and archive, with a form for a new item, an editor for one item, archive, restore and delete, and the projects themselves (add, rename, delete). [Focus](../ui/widgets/focus.js) starts, pauses, resumes and resets one timer and sets its length in whole minutes from 15 to 1440.

Each view creates its own stores for one lifetime and reads the core again whenever it is shown and when the window becomes visible, so a capture made in Today appears in Projects the next time Projects is shown. There is no shared module state between views; two views editing the same row are kept apart by the core's `expectedUpdatedAt`.

Keyboard focus never falls to the document. When a row leaves a list after it is completed, archived or deleted, focus moves to the same control on the next row, else on the previous row, else to the list's empty-state line or heading ([view-kit.js](../ui/widgets/view-kit.js)); Close in the Projects editor gives it back to the item's own button; and a Focus control hidden by its own press hands it to the control that replaced it. Delete in Projects asks once more: the armed button reads Confirm delete, its status line says which item or project it will delete, and Escape, moving focus off it or showing the view again disarm it. A row says Unsaved edit only once one of its fields has changed. The end of a focus session is said in Focus's status line. A failed read of the items is not shown as an empty store: Projects hides its counts, list and empty-state line, Today hides its note and task cards, and both show the error with Try again above their content.

## Items and projects

[items.js](../ui/items.js) is the only place the restart's views write items. It reaches the core through `items.list`, `items.get`, `items.save`, `items.delete`, `projects.list`, `projects.save` and `projects.delete` and nothing else.

- An item is archived when its `stage` is `done`, or when it is a task with `done` set, as in the prototype's [item-workflow.js](../dist/item-workflow.js). The views write both fields together: archiving sets `stage` to `done` and, for a task, `done` to true; restoring sets `stage` back to `previousStage` (or `inbox`) and `done` to false. A row another writer stored with only one of the two set is read by the same rule.
- The caps are the prototype's: 300 items, 30 that are not archived, and 30 projects, refused before the save with the prototype's sentences. The core does not enforce them; [issue 128](https://github.com/OpenCoven/open-sesame/issues/128) asks the owner whether it should, and whether it should keep `done` consistent with `stage`, before the MCP server in issue 81 writes items.
- A create names a client UUID v4 that is kept with its draft until the core confirms it, so a retry after a failure or a lost reply keeps one row. A draft changed after a reply was lost is looked up first and edited rather than duplicated. This holds for Today's field and for a palette capture, whose draft ID the palette keeps with its text, while the view that saves it stays on.
- Every edit names the `updatedAt` it started from. A conflict is reported, overwrites nothing and keeps the draft. In Projects the fields the person did not edit then show the newer row, and saving again writes only the fields the person edited, so it never replaces another writer's change to a field the person was not shown. If another writer changed the item's kind, nothing is saved: once Projects has read the change, Save sends nothing, and a Save sent before that is refused by the core as a conflict. The draft stays in its own kind's fields for the person to copy, also when the item is closed and opened again, and Discard changes opens the item as its new kind.
- Nothing is shown as saved until the core answers with the stored row. A read that was answered before a save committed cannot undo that save on screen, and a read overtaken by a later one is ignored.

A captured draft is saved with the fields the prototype's capture form used: a note of several lines is titled by its first line and keeps the rest as its body, a task keeps its lines in its text, and a bookmark needs an address.

## Focus

[focus-model.js](../ui/focus-model.js) stores one session in the core setting `focus.session` as its length and its start, deadline and pause times. The time shown is worked out from those times and the clock every time it is drawn, never counted down, so hiding the window, a sleeping machine or a relaunch cannot make it drift. A view redraws once a second while a session runs only to refresh the display. Reads wait for writes still out. A stored value this version cannot read is kept and reported, and is replaced only when the person chooses Start over. Known limit: the times are the system clock's, so if the clock is set back during a session, the session shows its full length until the clock passes its start again, and a pause in that time gives back the minutes already used; carrying on from the last reading instead would end a session early if the clock was later set forward again.

## Command palette

Typed text offers Capture note and Capture task commands for Today; `note:`, `task:` and `todo:` choose one kind, and text that starts with `/` or `!` is never a draft. Capture a note and Capture a task, with nothing typed, open Today's field with the kind chosen. A capture typed in the palette is saved under its own draft and never replaces Today's field. It counts as saved only when Today answers that it was: if it fails, or never runs because another view opened before Today was ready, the palette keeps its text and draft ID and the shell notice keeps the reason, until it is saved or the person closes the palette with the field empty. A search typed over the kept text does not replace it.

[palette-answers.js](../ui/palette-answers.js) is an ES-module port of the prototype's [calculator](../dist/calculator.js) and [world clock](../dist/world-clock.js). An answer is shown first and invokes no command. An answer with a result replaces the capture offers, so Enter on a sum or a time question copies the result instead of saving a note. An answer that is only an error, such as "Finish the expression to calculate." for a phone number, leaves the capture offers, but Enter does not choose them.

## Verification

The headless checks are [check-ui-items.mjs](../scripts/check-ui-items.mjs), [check-ui-focus.mjs](../scripts/check-ui-focus.mjs), [check-ui-palette-answers.mjs](../scripts/check-ui-palette-answers.mjs) and the views section of [check-ui-shell.mjs](../scripts/check-ui-shell.mjs). They pin the archive rule, stage patch, excerpts, titles, calculator and world clock to the prototype's code in node:vm (the one difference: the excerpt's tag step replaces a tag with a space rather than removing it, so that step never joins the text around a tag into another one; an excerpt can still hold text shaped like a tag and is shown with textContent only), and drive the stores over an in-memory stand-in for the core's commands ([ui-storage-core.mjs](../scripts/fixtures/ui-storage-core.mjs)), which is not evidence about the Rust core.

The [views browser fixture](../scripts/fixtures/ui-views-browser.mjs), run as `node scripts/fixtures/ui-views-browser.mjs build/ui-views-browser`, renders the three views in Chromium and WebKit against a synthetic host kept in the fixture process, so closing the page and opening a new one is a relaunch. It injects failed and lost writes, refuses and records every request off its loopback origin, runs each page on a paused fake clock and sends synthetic visibility changes. It covers palette capture into Today and Projects, relaunch, a palette capture kept when another view opens before Today has loaded, an edited palette retry after a lost reply that keeps one row, answers that save nothing, drafts kept through failures, stored markup shown as text, an edit refused across another writer's change of kind, a kept draft reopened in its own kind's fields after such a change, the active cap, Projects edits through a failure and another writer's change, archive and delete, projects, a focus session across hide, show, sleep and relaunch, a refused focus write, an unreadable stored session, a narrow window, keyboard focus after a row leaves a list, around the timer and after Close, the Unsaved edit mark, an armed Delete said and disarmed, the end of a focus session said, and a failed read of the items. `UI_SHELL_ENGINES` and `UI_SHELL_HEADLESS` select engines and a windowed browser as for the shell fixture.

A launched development app on one system is separate evidence: start it with `OPEN_SESAME_DEV_CONFIG_DIR` set to a disposable absolute folder so nothing is written to the person's data folder, capture a note and a task from the palette, quit, relaunch and find both in Today and Projects, and keep a running focus session through hide, show and relaunch. Windows and Linux hand checks of these steps belong to [issue 78](https://github.com/OpenCoven/open-sesame/issues/78).
