# Desktop interface and account updates

Projects now opens a shared collection workspace with Notes, Bookmarks, Tasks and Recent tabs. These use the same segmented navigation as Focus and Console, with left/right arrows and Home/End support. Changing collections preserves the current project and respects an editor that cannot finish saving. The overview cards and their floating arrow controls are removed; the sidebar shows items directly instead of category accordions. Project assignment, archive access, search, capture, bookmark previews and existing saved content remain available.

The music source bar uses one flat surface with a compact provider selector and fitted actions. Text input focus keeps its normal border instead of the bright nested outline; keyboard focus remains visible on buttons and tabs, and forced-color mode retains an input focus indicator. Console headers have a smaller segmented bar, a quiet connection status and an accessible refresh icon. Shells no longer offers familiar conversations; saved legacy familiar launchers open as shells, and each shell row displays its assigned project without increasing row height. Familiar messaging remains in Console → Familiars.

Quick search measures the input and command content independently of the current native viewport, so a previously collapsed window does not constrain its next size. Native launcher positioning uses an eight-pixel inset instead of the full widget's centering and size rules, and the WKWebView under-page surface is dark. The tests check collapsed, command-list and multiline sizing. Rendered fit still requires an installed visual pass because computer-use services were unavailable during this change.

## Spotify in the installed Mac app

Focus → Music → Spotify → Connect now starts a native system-browser authorization session and returns directly to the installed app through `opensesame-spotify://auth/callback`. Configure a public Spotify client ID under App setup and register that exact redirect URI in the same Spotify developer application. There is no client secret. The native process creates random state and an S256 PKCE verifier, checks the callback scheme, host, path and unique state/code, exchanges the code over HTTPS and checks the account with Spotify. Tokens stay in native memory for the app session and are cleared on disconnect or Open Sesame sign-out; only account display name, expiry and connection state reach the page. Provider HTTP redirects are rejected. See Spotify's [PKCE flow](https://developer.spotify.com/documentation/web-api/tutorials/code-pkce-flow) and [custom scheme support](https://developer.spotify.com/blog/2025-02-12-increasing-the-security-requirements-for-integrating-with-spotify).

A public client ID and provider-side registration are still required; no real Spotify login was performed during this change. Spotify's embedded player has its own playback session and account requirements. Connecting the native account does not make a full-playback claim or transfer browser cookies into an embedded player. Apple Music and Google retain their existing HTTPS-browser setup paths.

## Agent process management

Console → Processes provides Pause process, Resume process for suspended processes, and Stop with an inline confirmation. These are OS process controls, distinct from a familiar's conversation, task progress or approval state. Stop sends SIGTERM to the selected process; it does not force-kill a process tree or replay a previous prompt. The dashboard refreshes after an action and reports that a signal was sent before relying on the next observed OS state.

Only recognized agent executables owned by the current user receive short-lived control capabilities. Every operation validates its action, positive PID, capability expiry and freshly read process identity before signaling. Exited, replaced, foreign-user and unrecognized processes are rejected. A stop confirmation is bound to the same capability and is invalidated if that identity changes. Process arguments remain private in backend memory; they are not returned to the dashboard. Control tests mock signals rather than operating on real user agents.

## Verification

Validation includes the widget check suite, Projects keyboard and unsaved-editor tests, native launcher geometry tests, simulated dashboard management actions and stale-confirmation rejection, Python identity/capability controls, native Spotify PKCE/callback checks, existing WorkOS authentication and native view geometry checks, HTTP login preview checks and an arm64 macOS build. The pre-integration real PTY suite stalled and was stopped. This source adopts main’s PTY shutdown repair and bounded verifier; the final unified receipt must establish the combined result without erasing that original failure. Native visual fit, live Spotify authorization and real user agent management remain separate installed acceptance checks. WorkOS Waitlist and the Vercel hostname setup retain their previously documented pending provider settings.
