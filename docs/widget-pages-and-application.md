# Widget pages and application workspace

New declarative widget packages use `schemaVersion: 2` and a required `page`: `focus`, `media`, `projects`, `console`, `reader`, `live` or `widgets`. Installation adds a separately named tab on that page. The package validator, editor schema, scaffold and three starters share the same contract. Existing v1 packages stay under Widgets; installation does not rewrite them or discard configuration, drafts or previous definitions. Replacing or rolling back a definition updates the destination without duplicating the instance. The Tools manager retains preview, export, configuration, replacement and removal.

Page tabs reuse the existing navigation and preserve mounted native panes, timers, PTYs, playback and drafts. Arrow keys, Home and End include both built-in and installed tabs. Widget content fills its page; unrelated capture controls are hidden while it is selected. Source loading and actions are explicit. Reads are bound to the selected instance and configuration, and are retired on edits, page changes, collapse, replacement, removal and handoff. Preview and installation never contact a provider or execute an action. Hidden pages remain hidden even when they retain a widget selection.

GitHub declares Projects as its destination. Choose Widgets → GitHub → Add to Projects to install and open its tab. Repository management is a compact disclosure; removing the widget preserves the private local repository registry. Five UX changes are a unified repository toolbar; Overview/PRs/Issues/Actions tabs with recent-item counts; local search, status filters and sorting; workflow/branch/event/relative-time context; and responsive cards/rows with preserved focus, safe links and explicit unavailable/empty/stale states. Lists are recent samples of up to eight PRs, eight issues and six runs, not repository totals. Issue sampling skips pull requests before applying its eight-issue bound. GitHub access remains GET-only through the existing local CLI account; no token is copied into the renderer and the widget cannot merge, rerun or edit GitHub content.

The pop-out uses its actual window canvas with an application header, labeled activity navigation when space permits, visible display controls, docking and fill-screen actions. It remains open when switching applications. The native window is freely resizable and can become the main application window, with standard close/minimize/resize controls and a Dock presence while detached. Its content and running sessions stay in the same web view. Escape or explicit close returns it to the compact widget without ending sessions. Keep open is directly accessible in the compact activity rail; in the application header the same preference controls Keep on top. The native display menu pins the docked widget and the detached application to the selected display UUID, handles disconnection and moves the application into that display's visible bounds without imposing the widget's aspect ratio.

Shared UI polish uses flat dark dialogs, consistent tab bars, inputs, button sizes, quiet borders and keyboard focus states. Reading’s add flow has concise Article/PDF, RSS and Website tabs, one primary action, a consistent URL field and optional Advanced options. The detached canvas no longer depends on stale preset pixel dimensions or a WebKit animation frame to follow a window resize.

Focused synthetic checks, the unified Mac verifier, hosted CI, rendered Safari fixtures, native compilation/signature, live providers and installed acceptance are separate evidence classes. Fixtures use synthetic GitHub metadata and do not send a model prompt, capture real user audio/screens or type a command into an existing shell. Actual display relocation, native Dock behavior and real provider behavior require direct installed acceptance.
