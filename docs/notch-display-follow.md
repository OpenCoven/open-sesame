# Notch display following

The native notch previously preferred the screen already containing its panel, so moving the pointer to another display left the notch behind. The native host now resolves the global AppKit pointer against current screen frames, prefers that screen, and moves the existing panel to its top center. A lightweight 120 ms timer checks only eligible visible, docked notch placement and moves the window only when its target display or bounds change. Display configuration notifications refresh placement after a display is removed or rearranged. No accessibility or input-monitoring permission is requested.

The renderer receives the selected display's dimensions in logical points and recomputes Small, Medium, Large, Max and Full. Requested size is kept separately from the constrained frame, so crossing a smaller display cannot permanently shrink the preferred size. The native panel, web view, PTYs, media and familiar sessions are retained. A hidden panel stays hidden; reopening or using Option–Space chooses the pointer's screen. The shortcut opens rather than toggling away a launcher that was on a different display.

Following pauses while a mouse button is held, during live resize, and while an app modal, file picker, attached sheet, WorkOS or Spotify authentication interaction is open. Detached floating windows keep their manual placement. Menu and quick-search placement select the pointer display on opening rather than continuously following it. Mirrored screens retain a stable selection, and points in a display-layout gap retain a valid previous screen.

`desktop/tests/ScreenPlacementTests.swift` executes the actual placement model with synthetic adjacent, offset, negative-origin, stacked, mirrored, removed and small display geometry. It checks pointer priority, shared-edge ownership, invalid data, retained sizing, bounds, Full, launcher/menu anchors and interaction eligibility. `scripts/check-display-follow.mjs` executes the renderer's screen selection and change listener against authoritative native dimensions and stale WKWebView dimensions. `npm run verify` additionally compiles the complete native host and preserves the existing real PTY and origin/cleanup assertions. Initial focused compilation exposed a missing CoreGraphics import and ambiguous nonfinite test literals; both were corrected before the successful focused run.

Physical acceptance remains a separate check: on two displays, move the pointer between them with the notch collapsed and expanded, including mixed resolutions/scales and a display above or left of the primary. Confirm top-center alignment, fitted content, no focus theft and retained sessions; open Option–Space on each screen; drag/resize and open a picker to confirm movement waits; detach to confirm the window stays fixed; disconnect a display to confirm recovery. Compilation and synthetic geometry do not establish this observed device behavior. Exact local/hosted/build/install evidence and remaining GUI limits are indexed in the common-Git task record for `notch-pointer-display-20261108`.
