# Shared mobile renderer

[Issue #36](https://github.com/OpenCoven/open-sesame/issues/36) adds responsive presentation to the existing authored renderer. It does not establish an iOS/Android host or a desktop connection. The authenticated macOS host keeps its existing compact and detached behavior; the mobile shell activates only in a non-native renderer at viewport widths through 1024 CSS pixels. The sign-in-only HTTP development preview is unchanged. Use the isolated browser fixture for local layout qualification.

## Owners and navigation

[mobile-shell.js](../dist/mobile-shell.js) mounts one header, Today section and five destination buttons alongside the existing page panes. Projects maps to `items`, Widgets to `plugins`, Focus to `focus`/`lockin`, and Console to the saved `agentsView`/`agents` owner. Today is a presentation overlay, never a new saved activity key. Destination navigation calls `changeScenario`, preserving the existing pane DOM and installed page tabs instead of calling the desktop home action that resets selection. Today’s content links intentionally select the matching built-in tab: Latest note opens that note, Tasks opens Tasks, Focus opens Agenda, and Reading opens Later. They use the existing tab handlers so an installed tool cannot obscure the requested content, while its retained draft remains available when reopened. Scroll containers are remembered by node identity between destinations. Timers, terminal sessions and familiar chat remain with their existing owners; presentation does not create a host, authorize operations, or fabricate a roster.

[mobile-model.js](../dist/mobile-model.js) projects the current project’s items using the canonical archive predicate. Today shows the latest active note by edit/create time, open/completed tasks, the existing focus clock, and Reader’s deduplicated saved-for-later count/link. Item, project, focus and Reader events refresh this projection. User text uses `textContent`. It reads live models rather than parsing a second copy of localStorage. Saved workspace keys, migrations, storage durability and native permission state retain their current owners.

Capture delegates to the existing command launcher, draft interpretation and submit handler. Its mobile dialog uses the visual viewport’s height/top for keyboard changes, makes surrounding controls inert while open, traps Tab within visible controls, and returns focus to Capture on dismissal. The existing launcher handles Escape and command back navigation before the final Escape fallback. Outside a local dialog/menu, mobile Escape returns to Today; desktop Escape retains its existing window behavior. Mobile presentation keeps the shell expanded and restores the prior expansion setting when returning to a desktop viewport.

## Visual scope and outstanding acceptance

[mobile-shell.css](../dist/mobile-shell.css) scopes charcoal, ivory and lilac tokens, bundled EB Garamond/Inter with system serif/sans fallbacks, safe-area padding, flexible Today cards, focus indication and reduced-motion/forced-colors rules to the mobile shell. It consumes the byte-exact crown/lotus from OpenCoven/brand and unmodified OFL fonts from Google Fonts, with immutable revisions, hashes and notices in [asset provenance](../dist/assets/mobile/README.md). This creates no new canonical brand profile. The approved v0.3 reference remains absent from this task’s source baseline. Dependency [#34](https://github.com/OpenCoven/open-sesame/issues/34) must supply that reference before visual parity can be accepted; pinned brand/font bytes alone do not establish parity. Host strategy [#35](https://github.com/OpenCoven/open-sesame/issues/35) remains separately owned and requires ratification before new host/transport work.

Five navigation buttons being reachable does not qualify every existing pane’s mobile layout. Full Projects/detail, installed-widget forms, familiar presentation, long text and screen reader flows still need review against the reference, along with physical-device keyboard, rotation and safe-area evidence. Desktop data handoff, real PTY/provider instances and installed native behavior require their own evidence. This renderer increment does not close #36 or the mobile epic.

## Checks

Run `node scripts/check-mobile-shell.mjs` for canonical projection/compatibility regressions and `node scripts/check-mobile-assets.mjs` for pinned asset/license and hash checks, then the existing layout, page-widget, window, Escape, asset-cache and branding checks through `npm run check`. The full Mac verifier remains `npm run verify`; run `npm run verify -- --portable` for the explicitly requested portable scope. Source must remain frozen during each verifier.

The optional [browser qualification](../scripts/fixtures/mobile-browser.mjs) uses lockfile-pinned Playwright Chromium and WebKit. Start an owned loopback static server from the repository root (`python3 -m http.server 4196 --bind 127.0.0.1`), then run `node scripts/fixtures/mobile-browser.mjs`. Set `SESAME_FIXTURE_ORIGIN` for another owned loopback port and `SESAME_FIXTURE_OUTPUT` to a receipt directory for screenshots. The fixture blocks external requests and uses synthetic in-memory items; it checks five destinations at 320×640, 390×844, 768×1024, 1024×768 and 844×390, live projection/editing, literal-text safety, capture draft and focus restoration, repeated pane identity, installed built-in/imported tab and draft retention, a real installed-widget scroll offset, timer deadline preservation, unsent shell and disconnected familiar drafts, duplicate-bootstrap listener counts, content-specific Today routing, reduced viewport height, large-text navigation and desktop transition. These observations do not prove installed-device support or live-provider behavior. Keep execution receipts, original failures and task ownership under the common Git directory as described in [work tracking](work-tracking.md).
