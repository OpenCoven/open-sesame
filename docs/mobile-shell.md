# Shared mobile renderer

[Issue #36](https://github.com/OpenCoven/open-sesame/issues/36) adds responsive presentation to the existing authored renderer. It does not establish an iOS/Android host or a desktop connection. The authenticated macOS host keeps its existing compact and detached behavior; the mobile shell activates only in a non-native renderer at viewport widths through 1024 CSS pixels. The sign-in-only HTTP development preview is unchanged. Use the isolated browser fixture for local layout qualification.

## Owners and navigation

[mobile-shell.js](../dist/mobile-shell.js) mounts one header, Today section and five destination buttons alongside the existing page panes. Projects maps to `items`, Widgets to `plugins`, Focus to `focus`/`lockin`, and Console to the saved `agentsView`/`agents` owner. Today is a presentation overlay, never a new saved activity key. Destination navigation calls `changeScenario`, preserving the existing pane DOM and installed page tabs instead of calling the desktop home action that resets selection. Today’s content links intentionally select the matching built-in tab: Latest note opens that note, Tasks opens Tasks, Focus opens Agenda, and Reading opens Later. They use the existing tab handlers so an installed tool cannot obscure the requested content, while its retained draft remains available when reopened. At widths through 600px, Projects presents the collection and selected detail one at a time. Back calls the existing Projects owner’s `closeDetails()` method, respects the note-save veto, and returns focus to the collection. Collection tabs use the same canonical `libraryOpen` view flag; tablet and native layouts retain their split view. Short landscape Projects, Focus Agenda and Widgets panes scroll at the pane boundary so fitted rows, timer controls and catalog cards remain clickable. Note prose/source text scales with the root text size. Scroll containers are remembered by node identity between destinations. Timers, terminal sessions and familiar chat remain with their existing owners; presentation does not create a host, authorize operations, or fabricate a roster.

[mobile-model.js](../dist/mobile-model.js) projects the current project’s items using the canonical archive predicate. Today shows the latest active note by edit/create time, its plain-text excerpt and project, open/completed task counts and up to three real task rows, the existing focus clock, and Reader’s deduplicated saved-for-later count/first link. Completing a Today task calls the existing archive transition; reading opens the existing Later collection and selected entry. A familiar entry reads the canonical connected/selected snapshot and explicitly says Desktop not connected when unavailable. Item, project, focus and Reader events refresh this projection. User text uses `textContent`. It reads live models rather than parsing a second copy of localStorage. Saved workspace keys, migrations, storage durability and native permission state retain their current owners.

Capture delegates to the existing command launcher, draft interpretation and submit handler. Its mobile dialog uses the visual viewport’s height/top for keyboard changes, makes surrounding controls inert while open, traps Tab within visible controls, and returns focus to Capture on dismissal. The existing launcher handles Escape and command back navigation before the final Escape fallback. Outside a local dialog/menu, mobile Escape returns to Today; desktop Escape retains its existing window behavior. Mobile presentation keeps the shell expanded and restores the prior expansion setting when returning to a desktop viewport.

## Visual scope and outstanding acceptance

[mobile-shell.css](../dist/mobile-shell.css) scopes charcoal, ivory and lilac tokens, bundled EB Garamond/Inter with system serif/sans fallbacks, safe-area padding, flexible Today cards, focus indication and reduced-motion/forced-colors rules to the mobile shell. It consumes the byte-exact crown/lotus from OpenCoven/brand and unmodified OFL fonts from Google Fonts, with immutable revisions, hashes and notices in [asset provenance](../dist/assets/mobile/README.md). This creates no new canonical brand profile. The approved v0.3 reference is recovered as the supplied source ZIP and byte-identical standalone HTML, SHA-256 `f9fbd88673b3cdfc754540ad864fd58c34b47498bbae95c8e5d0555fb7de281a`; dependency [#34](https://github.com/OpenCoven/open-sesame/issues/34) retains independent ownership of its preservation. The port uses its charcoal/ivory/lilac palette, date/greeting, doorway geometry, paired Focus/pale-note essentials, ruled tasks/reading, violet navigation marker, crown Console glyph and initial-seal vocabulary. Actual application content and existing rich controls replace the specimen’s sample content and simplified controls. No prototype script, storage key, demo identity or scripted reply is a production dependency. Host strategy [#35](https://github.com/OpenCoven/open-sesame/issues/35) remains separately owned and requires ratification before new host/transport work.

Five navigation buttons being reachable does not qualify every existing pane’s mobile layout. The browser fixtures cover shell navigation, full-width Projects editing, canonical transport lifecycles, reference-derived presentation and installed declarative forms in every page adapter. Human screen reader flows and other untested built-in states retain their own qualification needs, along with physical-device keyboard, rotation and safe-area evidence. Desktop data handoff, real PTY/provider instances and installed native behavior require their own evidence. This renderer increment does not close #36 or the mobile epic.

## Checks

Run `node scripts/check-mobile-shell.mjs` for canonical projection/compatibility regressions and `node scripts/check-mobile-assets.mjs` for pinned asset/license and hash checks, then the existing layout, page-widget, window, Escape, asset-cache and branding checks through `npm run check`. The full Mac verifier remains `npm run verify`; run `npm run verify -- --portable` for the explicitly requested portable scope. Source must remain frozen during each verifier.

The optional [browser qualification](../scripts/fixtures/mobile-browser.mjs) uses lockfile-pinned Playwright Chromium and WebKit. Start an owned loopback static server from the repository root (`python3 -m http.server 4196 --bind 127.0.0.1`), then run `node scripts/fixtures/mobile-browser.mjs`. Set `SESAME_FIXTURE_ORIGIN` for another owned loopback port and `SESAME_FIXTURE_OUTPUT` to a receipt directory for screenshots. The fixture blocks external requests and uses synthetic in-memory items; it checks five destinations at 320×640, 390×844, 768×1024, 1024×768 and 844×390, live projection/editing, literal-text safety, capture draft and focus restoration, repeated pane identity, installed built-in/imported tab and draft retention, a real installed-widget scroll offset, timer deadline preservation, unsent shell and disconnected familiar drafts, duplicate-bootstrap listener counts, content-specific Today routing, reduced viewport height, large-text navigation and desktop transition. These observations do not prove installed-device support or live-provider behavior. Keep execution receipts, original failures and task ownership under the common Git directory as described in [work tracking](work-tracking.md).

The optional [transport lifecycle fixture](../scripts/fixtures/mobile-transport.mjs) runs via `node scripts/fixtures/mobile-transport.mjs` against the same owned loopback server. Playwright replaces only the bridge script with a deterministic in-memory transport; actual xterm, the pinned Coven runtime/client, familiar UI and navigation run unchanged. It checks the same terminal backend ID/node/buffer and unsent draft across repeated navigation, one open with no unintended input/close, and a pending synthetic chat turn streaming while hidden with stable history nodes, next-turn draft and reading anchor. Chat input and Stop remain reachable through phone/tablet landscape resizing while the same turn is pending. No real PTY process, account, provider or companion is involved, and no production flag or authority route is added.

The [pane layout fixture](../scripts/fixtures/mobile-pane-layout.mjs), run with `node scripts/fixtures/mobile-pane-layout.mjs`, exercises full-width note details at 320px, 390px and 568px landscape, title editing, Back and save veto, collection reopening, 200% note prose, pointer reachability for Projects, Focus and Widgets in short height, and the existing tablet split. These checks complement the shell fixture; other pane interiors and exact reference styling still require qualification.

## Reference-derived presentation

Run `node scripts/fixtures/mobile-visual.mjs` against the same owned loopback server for palette, paired essentials, single-line timer numerals, italic font loading, crown navigation, real task completion, home-capture focus return and honest disconnected familiar behavior. It seeds a deliberately separate prototype storage key and proves that key cannot populate production Today. `SESAME_FIXTURE_OUTPUT` saves screenshots for comparison with the exact reference. Browser observations establish the tested presentation and interaction states; human visual/device acceptance remains separate.

Familiar seals are decorative projections of canonical IDs and display names: a stable ID-derived shape and first grapheme, with no persisted mobile identity or capability state. Explicit custom avatar images stay intact. Phone rosters form a horizontal tab strip with matching arrow-key orientation; wider layouts retain the original sidebar. At compact landscape height, the existing rail owner supplies the default collapsed conversation view without writing a preference. Opening the list displays the chooser; choosing a familiar closes it through the existing rail owner. Existing explicit rail preferences remain authoritative, and desktop behavior stays outside the mobile scope.

## Installed forms and task scrolling

Run `node scripts/fixtures/mobile-forms.mjs` against the owned loopback server for all seven installed page adapters, all four declarative component types, editable configuration, long content, saved configuration and local note actions at phone, tablet and short landscape sizes with normal and enlarged text. The fixture archives its own saved notes through the canonical owner to respect the active-item limit. It also creates a list, creates and edits shared tasks through the actual Task Manager form. No native bridge, provider or external website is involved.

In the mobile scope, the installed page view owns Task Manager scrolling. The form, filters, list and pagination follow normal document flow so a tall form cannot reduce the task list to zero height. Navigation preserves that page container’s scroll position; the native desktop list keeps its original layout. Mobile installed content, task labels and actions use relative text sizes, and controls wrap to the available width.

## Built-in interiors

Run `node scripts/fixtures/mobile-interiors.mjs` against the same loopback server to exercise Calendar scheduling and Escape/focus return, editor Tab containment, Reader pagination with long cached articles and exact reading-anchor return, and Tools preview/install/dismissal in Chromium and WebKit at phone, tablet, enlarged-text and short-landscape sizes. The fixture uses canonical owners and synthetic local data, blocks external requests and starts no provider or native operation.

Mobile Calendar controls wrap within the pane and the editor fits the visual viewport with scrolling controls. The existing calendar owner retains validation, scheduling, timer behavior and dismissal; explicitly tabbable editor buttons preserve its keyboard loop in WebKit. Mobile Reader uses a horizontal article strip on phones while retaining canonical pagination and selection. The pagination owner measures the rendered row height so enlarged sidebar entries still fit their pages. The article keeps its existing scroll owner and progress calculation; the pane scrolls when the surrounding controls need more space. Reader’s inline quick-capture footer is omitted in the mobile reading view, with Capture still available in the header. Tools retains its native dialog and existing installation owner, enlarges text and returns focus after the dialog closes; opening an installed page intentionally hands focus to that page instead.
