# Current capability and acceptance matrix

This matrix distinguishes implemented surfaces from evidence of operation. Use the [current-state lookup](work-tracking.md#find-current-work) to find exact source and check receipts. This table describes source contracts, not a live survey of the current machine or account. Historical browser reviews do not establish native or physical-device acceptance.

iOS/iPadOS and Android support are not implemented or qualified in this baseline. The current [mobile host ADR 002](mobile/adr-002-mobile-host.md) makes iPhone and iPad a Tauri 2 target of the desktop app and supersedes [ADR 001](mobile/adr-001-mobile-host.md), which separates the local workspace from connected familiars, records the earlier approved direction and links the [future capability/state contract](mobile/capabilities.md). It changes no existing Mac or HTTP-preview authority.

## Built-in remote desktops

Console → Desktops supports direct VNC host/port connections in the authenticated Mac app, secure `wss://` RFB gateways in Mac and browser, and existing HTTPS web viewers. The native bridge opens only explicitly requested sessions from the bundled main document; it does not expose a network listener. Ordinary direct TCP does not encrypt the desktop stream; use a trusted network or an independently secured transport. Tailnet and Local labels do not discover machines or establish network access.

Connect explicitly, enter credentials when requested, and optionally remember them in macOS Keychain. Browser credentials stay in memory. Sessions offer fit/actual size, view-only, fullscreen, Ctrl-Alt-Del, manual text clipboard transfer, disconnect and reconnect. Up to four built-in connections can remain open while switching tools. Logout, reload and exit close them. Existing HTTPS viewer pages retain their separate authentication and cannot report an RFB handshake to Open Sesame.

Real installed-app, macOS Screen Sharing, standard VNC server and secure gateway acceptance remains pending; local transport and controller tests alone do not establish interoperability.

Reusable declarative tools provide local import, fixture preview, declared page categories, installed page tabs, expandable manager cards, launcher navigation and explicit approved actions. GitHub summaries use existing connected repositories; feed headlines use saved Reader data. See [tool creation and submissions](tools.md). Automated contract/UI tests and native compilation do not establish rendered layout or live-provider acceptance.
