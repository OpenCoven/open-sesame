# Native capture, avatars and media

## System audio

In Live, choose **System audio** or **Microphone + system audio**, choose Transcribe or Record audio, then Start. The installed Mac app uses ScreenCaptureKit audio capture instead of browser `getDisplayMedia`; macOS 13 or later is required by the existing app. System-only capture does not request microphone access. The combined source also requests microphone access, and transcription requests Speech Recognition. macOS controls Screen & System Audio Recording access under Privacy & Security; denial produces an actionable message and leaves capture stopped. Access is requested only after Start. See Apple's [audio capture configuration](https://developer.apple.com/documentation/screencapturekit/scstreamconfiguration/capturesaudio).

Only audio outputs are subscribed to; no screen image is read or saved. A bounded native timeline aligns system and microphone PCM and mixes them into a 48 kHz mono stream without playing it through the speakers. Transcribe appends PCM to Apple's speech request and creates no audio file. Record audio writes an AAC M4A file in private temporary storage; Stop finalizes it before Save audio becomes available. Clear and sign-out discard retained recording data. Capture stops on cancellation, source errors, sign-out and application shutdown. The existing Live transcription segmentation and 30-minute capture limit remain; segment boundaries and physical-device fidelity require a real audio pass.

Native buffer tests check source mixing, finite/clipped levels, bounded storage, stale input rejection, independent CMSampleBuffer copies and sample fidelity without requesting permissions or capturing audio. Browser source support remains constrained by that browser's sharing and speech APIs. Compilation and synthetic buffers do not establish macOS permission prompts, actual system/microphone capture, codec fidelity or speech-service acceptance on hardware.

## Familiar avatars

A familiar's default image is read from `avatars/` in its configured Coven workspace. A filename matching `<familiar-id>` wins, using PNG, WebP, JPG, JPEG, AVIF and GIF priority; otherwise the first supported image by case-insensitive name is selected. This follows [Cave's workspace convention](https://github.com/OpenCoven/coven-cave/blob/8bbb6d389de6b01f71c8755b9273df1c0839985d/src/lib/server/familiar-avatar.ts). Missing or unreadable images retain the familiar's emoji or icon.

Choose the avatar beside the selected familiar's name to select an image. The app creates a square PNG and explicitly saves it to `avatars/<familiar-id>.png` in the current authoritative workspace. It leaves identity, memory, conversations and other avatar images unchanged. No model prompt is sent. Directory handles and no-follow checks prevent avatar directory/file symlinks from redirecting a write, and the server validates PNG size, dimensions, structure, CRC and bounded decompression before writing atomically. Existing images are read only and rendered as bounded PNG thumbnails; thumbnails stay in process memory. A roster response has a total image budget. The native file chooser and live workspace appearance still require a GUI pass.

## Version, playlists and Media

The installed bundle's actual `CFBundleShortVersionString` appears beneath the activity rail, in the widget options header and on the sign-in screen. An unbundled preview says Development. The label is injected by the native host rather than copied from a hard-coded release string.

YouTube playlist-only links now declare `listType=playlist` and explicitly cue the playlist without autoplay; an explicit selected video is preserved. The playlist toggle lives in the source toolbar outside the native player hit region. Loading failures provide Retry playlist, and unavailable lists retain an accessible playlist toggle. Narrow or short player workspaces use an opaque list over the player; wider workspaces retain the side rail. Close, Escape and episode selection return to the player. This applies to the YouTube workspace when hosted in either YouTube or Music, and to local Media queues. Native embedded views are hidden while the DOM playlist overlays them. The player behavior follows Google's [playlist parameters](https://developers.google.com/youtube/player_parameters) and [IFrame queueing API](https://developers.google.com/youtube/iframe_api_reference). Private/restricted playlists and actual YouTube network playback require live provider qualification.

Media's existing file inputs now open a trusted, authenticated native sheet attached to the widget, with app activation. The chooser checks the actual main WKWebView document and refuses remote frames. A visible dropzone accepts audio/video files and folders, preserves relative paths, filters unsupported files through the same Media model and appends to the current playlist. Directory traversal is bounded. Opening or dropping files does not claim autoplay. The compact shell close confirmation uses a fixed grid, readable label/countdown and contained actions without the old red countdown surface; its cancellation deadline is unchanged.
