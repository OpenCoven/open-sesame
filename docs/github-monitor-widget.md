# GitHub project monitoring

Choose **Widgets → GitHub → Add to Projects**, then open **Projects → GitHub** in the Mac app. Open Sesame checks the existing GitHub CLI account without reading or copying its token into the widget. If GitHub CLI is missing or signed out, install it from its official site, copy the displayed sign-in command, run it in Terminal and complete GitHub’s browser flow. Return and choose **Connect**. The command is `gh auth login --hostname github.com --web --git-protocol https`; copying it does not execute it or grant new scopes automatically.

Open **Manage repositories** to add `owner/repository` or a credential-free `https://github.com/owner/repository` URL, then choose among up to 12 locally saved repositories. Overview presents recent activity in responsive cards; PRs, Issues and Actions provide focused lists. Search titles, authors, branches or workflow names, filter by status, and sort by update time, creation time, title or status. These controls operate on the loaded snapshot without another provider request. Workflow rows include workflow name, branch, event and relative update time. View and sort preferences are saved locally; search text is transient. Counts describe the bounded recent lists. These are bounded recent lists, not complete totals or GitHub Projects boards. Open a row on GitHub for the full discussion, checks or workflow log. Private repositories and organization SSO follow the selected CLI account’s existing access.

The host uses fixed REST endpoints through `gh api --hostname github.com --method GET`; it does not post, merge, rerun workflows, change issues or modify remote repository settings. Removing a repository affects only this local monitor. API method, hostname, endpoints, filters and credentials cannot be supplied by the web page. Repository paths reject credentials, queries, extra path segments and traversal. Titles and account labels render as text; result links are constructed from verified identities and checked again in the UI. Provider diagnostics, tokens and configuration are never returned or logged by the monitor.

Only the selected project refreshes, once per minute while the view is visible and the widget is expanded. Closing, collapsing, switching page or hiding the app page stops polling. A 60-second cache and a 15-second manual-refresh floor prevent repeated clicks from flooding requests. Rate limiting pauses network access for five minutes. Transient failures retain a labeled, timestamped snapshot; authentication loss or a detected account switch clears private cached data. Unavailable workflow or issue permissions are labeled for that section rather than fabricated as success.

Repository names are stored under the app’s `github-monitor` support folder, using a private 0700 directory, 0600 files, a stable advisory lock and atomic settings replacement. Symlinked or nonprivate settings fail closed. Repository metadata stays in memory and is cleared on bridge shutdown. The app uses no embedded GitHub client secret, personal token, analytics or background agent. Existing `gh` credentials remain managed by GitHub CLI.

Automated tests cover the real subprocess argument contract, output/cancellation bounds, token/error redaction, URL rejection, private settings, cached/offline/rate-limit behavior, account changes, bounded section data and the visible-only dashboard lifecycle. A live read-only check on November 8 connected the existing CLI account and retrieved OpenCoven/open-sesame metadata and six workflow runs, without GitHub mutations. That read check is separate from installed rendering, user sign-in and other organizations’ SSO or permissions. The transport follows the [GitHub CLI API manual](https://cli.github.com/manual/gh_api) and [workflow runs REST documentation](https://docs.github.com/en/rest/actions/workflow-runs).
