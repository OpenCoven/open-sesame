# Familiar access and conversation layout

Familiar chat starts read-only. The Access menu beside the composer offers **Full access · ask** for the next reply. Sending that reply opens a native confirmation naming the familiar, engine, starting workspace and beginning of the exact message. Cancel is the default keyboard action. Full access is unrestricted by the workspace: the engine can edit or delete files, run commands and use the network without further permission prompts. The choice resets to read-only after every attempt; it is never remembered as a standing permission. Stop interrupts the owned reply but cannot undo completed work.

The run command in the inspected Coven CLI supports `read-only` and `full`; a workspace-only write mode is not advertised here. The app does not interpret model prose, tool output or slash commands as an approval. Normal read-only discovery, conversation opening and messages do not require redundant confirmation. Selecting an avatar prepares a separate native confirmation for replacing only `avatars/<familiar-id>.png` in its canonical workspace. Cancel keeps the existing avatar. Microphone and system-audio consent remain explicit native OS flows initiated from voice controls; a Familiar grant cannot grant OS permissions.

Native confirmations use a private stdio prepare/finish protocol. The web page can request an operation or cancel it, but cannot call either private method, choose a workspace, retrieve an approval token, or approve a proposal. A proposal owns an immutable copy of the request and binds the familiar, display name, engine, persistent conversation/revision/session, run ID, message and canonical workspace device/inode. Approval is consumed under the bridge instance lock before execution, expires after 90 seconds and disappears on bridge restart. It is not a durable permission shared between processes. The existing per-familiar file lock still excludes concurrent conversation writes from another bridge. Duplicate finish calls, denial, expiration, changed identities and wrong CLI policy attestation fail closed.

Changing familiar, engine, connection or view cancels a pending confirmation. Sign-out, bridge exit and application shutdown also cancel. A full-access draft stays in the composer until the first accepted run event, and cancellation restores the saved conversation. Native replies are still required to attest the exact workspace and approved policy and settle with the existing bound outer completion. Tests use the deterministic Coven fixture, never a real familiar or model.

The Familiar roster uses the same remembered rail toggle as Shells and Desktops, with an independent preference. Hiding it returns the toggle to the Console toolbar; reopening it restores the same mounted thread, selected familiar, draft, scroll and active reply. Its label, expanded state and controlled region remain available to assistive technology. Each rail keeps its own preference across launches.

The conversation body has a centered 780 px reading column, quiet compact user messages, more deliberate Markdown spacing and horizontally scrollable code/tables. The composer aligns to an 820 px maximum while fitting narrow widgets. Pending permission, thinking and connection states appear in the conversation before reply text arrives. The input focus stays quiet and the persistent session remains identified as Open Sesame. Native rendering and actual provider access must be checked separately from fixture, compilation and signing evidence.
