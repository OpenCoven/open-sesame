# Optional widgets and installation

Open Widgets, select a catalog widget, then choose Install widget, Deactivate widget, Activate widget or Uninstall widget. Installation and account connection are separate: installing or activating does not sign in, send a prompt or start recording. The account setup controls are available only while the widget is active. Every catalog entry supports these controls, including GitHub, Coven Familiars, Spotify, Apple Music, YouTube, Claude Code, Codex and RSS & Atom.

A fresh profile starts with exactly four active widgets: Agenda, Local Media, Tasks (Task Manager), and Shells. Reader and Transcribe start uninstalled, as do other optional views and providers. Inactive widgets do not appear in workspace navigation, view tabs, service choices or launcher suggestions. Widgets management remains available to activate them. Its default My widgets filter shows only active entries; the full catalog also shows available and inactive entries so they can be managed.

Explicit saved activation choices are preserved. Previously configured RSS subscriptions and explicit legacy GitHub installations retain their access during migration. Existing articles, notes, bookmarks, tasks, recordings, conversations and terminal settings are not deleted by hiding a widget. Built-in Tasks reuses the existing Projects storage and has one Tasks tab rather than a duplicate legacy task tab. [workspace-widgets.js](../dist/workspace-widgets.js) keeps native navigation and active imported page widgets aligned, and moves an inactive current view to an available view without remounting its saved content.

## Implementation and regression entrypoints

[widget-lifecycle.js](../dist/widget-lifecycle.js) loads before feature scripts and owns built-in state in `open-sesame-widget-lifecycle-v2`, migrating saved v1 choices while leaving the v1 record intact for older installed builds. It migrates explicit legacy GitHub installation and existing Reader subscriptions without rewriting their content stores. Once written, explicit inactive/uninstalled state takes precedence over those legacy records. Invalid saved lifecycle data is preserved and fails closed; failed storage writes do not change runtime state. Account connection status must never be used as installation status. Changes dispatch `open-sesame-widgets-changed` only after storage succeeds. Storage events synchronize built-in and imported activation with separate browser pop-out documents, so docking does not restore a stale installation.

Imported activation belongs to the existing instance record in `open-sesame-tools-v1`; [tools-model.js](../dist/tools-model.js) restores legacy records as active, while [tools.js](../dist/tools.js) owns persistence, launcher filtering and read invalidation. [page-widgets.js](../dist/page-widgets.js) derives active entries and retires mounts when an instance is deactivated or removed. Keep these lifecycle boundaries intact when adding a catalog entry or provider operation; guard callable APIs as well as visible controls. A new catalog ID must also be registered in the built-in lifecycle model and covered by its tests.

Run `node scripts/check-widget-lifecycle.mjs`, `node scripts/check-tools-ui.mjs` and `node scripts/check-page-widgets.mjs`, then the normal [verification workflow](development-workflow.md#implement--verify--review). The regressions cover fresh defaults, migration, persistence, corrupt/full storage, saved content and draft preservation, pending read retirement, reactivation and uninstall. Browser fixtures, native compilation, hosted CI, installed app acceptance and live provider results remain separate evidence classes.
