# Mobile design and delivery

The mobile host direction is ratified; mobile support is not shipped. [Issue #33](https://github.com/OpenCoven/open-sesame/issues/33) tracks the complete experience; its child issues separate reference, architecture, implementation, device qualification and packaging. Responsive desktop CSS, a prototype, a signed-in account or portable tests do not establish a mobile host or a companion connection.

Read [ADR 002: Tauri 2 iOS target](adr-002-mobile-host.md), which superseded the host choice in ADR 001 on 12 November 2026, then [ADR 001: mobile host](adr-001-mobile-host.md), the [source and transport inventory](source-inventory.md) and the [capability/state contract](capabilities.md) before implementing mobile features. The ADR records Val's explicit approval, the exact reviewed source/reference and the remaining implementation/delivery gates. Existing [macOS capabilities](../capabilities.md) and [development/authority rules](../development-workflow.md) continue to apply.

[Issue #34](https://github.com/OpenCoven/open-sesame/issues/34) is the design-reference dependency. At the ADR's source baseline, neither `examples/mobile-reference` nor `docs/mobile` existed on main, and #34 remained open. The exact v0.3 reference, editable theme, offline checks and asset/license provenance must be delivered and reviewed under #34 before presentation fidelity can be accepted. The ADR now reconciles the exact artifact in draft PR #49; its separate source delivery and acceptance gates remain open. These documents do not reconstruct or substitute for that specimen.
