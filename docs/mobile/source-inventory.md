## Bounded adapter decision required by #42

Assign the eventual native companion adapter to the mobile host/transport work, underneath `OpenSesameCovenClient`; retain canonical familiar, conversation, session, revision and run identities from their existing owners. Before implementation, document the selected authority and server owner, exact versioned operations and response/event limits, expected peer and pairing/grant scope, credential lifecycle, operation-specific approval, cancellation and generation retirement. Include receipt lookup for uncertain sends and rejection of reused request IDs with changed payloads. No generic URL/method proxy, new identity database or protocol is justified by this inventory.

Compare actual roster/open/history/send/stream/cancel mappings for each candidate, including whether Open Sesame can preserve its existing conversation history when changing hosts. If an adapter would substitute Chat history, a daemon mission or demo identities for the required application conversation, stop and resolve that mismatch with the canonical owner. Bound any missing host extension to those operations, review threat/compatibility tests and obtain approval before adding access. LAN discovery only supplies candidates; follow [Apple local-network privacy guidance](https://developer.apple.com/documentation/technotes/tn3179-understanding-local-network-privacy) for permission/denial and never treat discovery or Wi-Fi reachability as authentication.
