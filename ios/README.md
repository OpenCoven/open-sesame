# iOS and iPadOS local host candidate

This is the local implementation candidate for [#38](https://github.com/OpenCoven/open-sesame/issues/38), using the ratified Swift/WKWebView direction and canonical [workspace storage](../docs/workspace-storage.md). The deployment target is iOS 18/iPadOS 18. Source implementation, compilation, simulator tests and installed-device acceptance are different evidence classes. The remaining #37/#38/#41/#44 device and live-account criteria remain open; this is not shipped mobile support or an Android host.

## Build and inspect

Use Xcode with a Swift 6.2+ compiler, Python 3, Node.js and XcodeGen. The implementation was first compiled with Xcode 27.2. The [preparation script](../scripts/prepare-ios.py) verifies the exact existing WorkOS archive and every upstream file hash before compiling its unmodified sources offline for the selected SDK. It copies validated authored web assets into the task-owned generated tree and derives the native key contract from the canonical storage model. It provisions no account and changes no provider or signing settings.

```sh
python3 -B scripts/prepare-ios.py --sdk iphonesimulator
xcodegen generate --spec ios/project.yml
xcodebuild -project ios/OpenSesameMobile.xcodeproj -scheme OpenSesameMobile -configuration Debug -sdk iphonesimulator -destination 'generic/platform=iOS Simulator' -derivedDataPath build/ios-derived CODE_SIGN_IDENTITY=- ARCHS=arm64 build
```

The generated project is ignored. Simulator builds use local ad-hoc signing so Keychain works; an unsigned simulator build can launch while failing credential access. The development bundle identifier is `computer.opensesame.mobile.development`. Use a separately owned simulator and preserve unrelated applications/devices. For a device compilation without installation, prepare `--sdk iphoneos` and build with `-destination 'generic/platform=iOS' CODE_SIGNING_ALLOWED=NO`. A physical installation requires available, already-authorized signing resources and a device; this command does not provide them.

Run `xcodebuild test` against an explicit owned simulator identifier with a unique result bundle. [MobileGateUITests](UITests/MobileGateUITests.swift) exercises the production signed-out gate and system-authentication cancellation. [MobileIntegrationTests](Tests/MobileIntegrationTests.swift) injects a test-only native account policy into an isolated controller, uses real WKWebView/SQLite, and checks native adapter hydration, Unicode persistence, Focus reload, receiving rejection, suspension and logout retirement. That fixture does not sign in, create an authenticated identity, change production configuration or qualify live authentication. Its hardware protection test is explicitly skipped in a simulator; a skipped gate is not passing evidence.

Run `bash scripts/check-mobile-native.sh` for real-file SQLite transaction, checksum/Unicode, stale-writer, content comparison, interruption rollback, future-version preservation, export/recovery and native receiving-policy checks. This joins the Mac verifier. Run `npm run verify`, explicit `npm run verify -- --portable`, and the relevant workspace/mobile browser fixtures on the final source. Portable checks omit native execution. Keep the original failure, command, source identity, cleanup disposition and acceptance limits with each receipt.

## Receiving and lifecycle boundaries

[MobileApp.swift](Sources/MobileApp.swift) owns a single UIKit scene/container, native account controls, WKWebView and explicit file UI. It loads only the bundled local entry document and gives it read access only to its public asset directory. Main-frame navigation away from the entry is denied; explicit HTTP(S) links may open outside the privileged view. External frames receive no injected platform bootstrap and cannot access native operations through the receiving handler. [MobileBoundary.swift](Sources/MobileBoundary.swift) requires the exact owned web view, trusted local main frame and current per-document nonce, active native scene and unexpired verified account before allowing the bounded storage methods. Unknown methods, forged fields, credentials and renderer platform claims grant no authority. There is no Python/PTY service, companion transport or generic file/SQL/RPC route.

The renderer's explicit iOS flag selects its responsive shell and [native storage transport](../dist/workspace-native.js); it is not an authorization source. Canonical models hydrate before defaults execute. Desktop-native behavior retains its existing backend and receiver. The native host hides workspace content and accessibility on suspension, rejects inactive operations, retires the document on logout/expiry and closes receiving ownership on scene disconnection. Sign-out first checkpoints the open editors through the canonical storage owner; a failed flush offers keeping the workspace open for recovery. Retirement takes a best-effort bounded snapshot through canonical editors for explicit recovery export after verified sign-in. These retained buffers are memory-only recovery aids, not successful persistence or a guarantee after process termination. Per-edit persistence acknowledgments remain authoritative; a best-effort suspension flush cannot promise unacknowledged text survived process termination.

Authentication reuses [the existing verified WorkOS owner](../desktop/Authentication.swift), public client, PKCE/callback validation and signed user binding. UIKit supplies its system-browser presentation and a separate `WhenUnlockedThisDeviceOnly` Keychain service. Tokens, refresh credentials, sealing material and verified account metadata never enter renderer exports or storage. Local offline restoration uses only native Keychain attestations from prior successful signature/user verification, an unexpired token and a matching continuous-time anchor. A clock discontinuity or unverifiable reboot anchor requires online verification; data is retained. No production callback, sign-out or registration setting is changed by this build. Existing saved settings and real iPhone/iPad sign-in/revocation still need current readback and live acceptance.

## Durable data and files

[WorkspaceStore.swift](Sources/WorkspaceStore.swift) stores the same serialized generations beneath existing owners in Application Support. It requests and verifies SQLite WAL/FULL, validates the generated key allowlist and SHA-256, compares revision and expected content in a transaction, preserves current/previous/recovery records and returns an acknowledgment only after commit. Unknown database versions are rejected before changing journal settings. Interrupted uncommitted transactions roll back; uncertain commit outcomes block renderer writes until reconciliation. It adds no competing item, Focus, identity or permission model.

The directory/database/journal policy is complete file protection, with committed user data included in normal app-data backup. Temporary exports are regenerable temporary files and use complete protection. Physical locked-device behavior, journal protection and consistent operating-system backup/restore remain explicit hardware gates. The simulator's filesystem cannot prove them.

Workspace files is a native, explicit-action menu for saved JSON export, open-draft recovery, a content-free recovery report, validated import and previous-generation restoration. [MobileFiles.swift](Sources/MobileFiles.swift) creates real UTF-8 files, bounds reads before allocation can grow past the limit, checks the saved generation and excludes credentials/transport keys. Import selects a file, validates through the existing model, asks for explicit replacement, checks the preview revision and retires the old owner before reload. Recovery restores through the same model and retains the damaged original. Logout preserves workspace data. User-authored text can itself contain sensitive information; these exports are ordinary local files, not an encrypted sync/backup service.

## Remaining acceptance

Real iPhone and iPad sign-in/cancel/logout/revocation, protected-data denial and unlock, termination/relaunch, backgrounding, clock changes, keyboard/safe areas/rotation, VoiceOver/large text, and Files/share Unicode round-trip remain required. Device-target compilation, a synthetic account fixture and a readable temporary file do not satisfy those device interactions. Native shell/reference integration retains the published #36 owner source and its provenance; reference approval and installed-device parity remain separately recorded. Keep the full issue acceptance audit and mutable machine-specific receipts in common Git storage.
